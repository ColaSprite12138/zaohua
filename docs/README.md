# 文档地图（先看这里）

## 一句话规则

**按「变更频率」分层，不按主题分层。** 一份文档只放一种频率的内容 ——
这是 `game-design.md` 变胖的唯一原因：它同时装着"三年不变的愿景"和"每天都在变的进度"。

## 目录

| 文件 | 放什么 | 多久变一次 |
|:--|:--|:--|
| `design/game-design.md` | **规则 + 理由**（"为什么这样"）。章节号是外部锚点 | 很少变，**冻结式增长** |
| `design/<module>.md` | 单模块设计草稿（技能库 / 装备公式 / AI…） | 设计期高频，定稿后回写主文档 |
| `design/skills-batch-1.md` | 技能库批次一（草稿，未并入 9.3） | 设计期 |
| `design/net-sync-design.md` / `net-sync-v2.md` | 帧同步设计（已是独立册，参照它做） | 中 |
| `assets/*/CONTEXT.md` | **代码契约**：改这里会破什么、不变量、依赖方向 | 随代码 |
| `assets/*/EXPERIENCE.md` | 踩坑经验（"下次别踩"） | 随踩坑 |
| `status/implementation.md`（**待建**） | 进度：做完了什么、验到什么程度 | **每周** |
| `decisions.md`（**待建**） | 决策索引：一行一条 + 链接到细节 | 每轮追加 |
| `HANDOFF.md` | 交接：现在能跑什么、门禁、回滚基线 | 每批 |
| `feedback.md` | 引擎 / SDK 的问题与绕过 | 遇到就写 |

## 四条规矩

1. **一份文档只放一种变更频率。** 设计定稿后，不再往里塞进度或流水账。
2. **章节号是锚点，旧正文不搬家，只分流。** `HANDOFF.md`、`CONTEXT.md`、`EXPERIENCE.md`
   里到处都是「§6.3」「设计 15.0」「§8.4」这类引用。搬一次要改十几处，还不一定找得全 ——
   所以旧内容留在原地，靠"新内容不再进来"止住膨胀。
3. **新设计先写 `design/<module>.md`**（草稿），定稿后才回写 `game-design.md` 对应章节
   + 一行指针。草稿被推翻时不污染正文。
4. **进度只写 `status/implementation.md`**，`game-design.md` 不再追加批次记录。

## 为什么不分得更细

`assets/` 已经有 5 个模块 × 2 份文档（`CONTEXT` / `EXPERIENCE`），再叠一层按模块的设计分册，
会变成"查一个答案要翻 15 个文件"。所以只给**真正长起来的模块**开册（目前是战斗、星图 / 技能），
其余仍留在主文档。**分册的成本是"多一个可能过期的地方"，不是零。**
