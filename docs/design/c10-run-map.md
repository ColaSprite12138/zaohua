## 10. 单局结构（15 分钟）

### 10.1 时间预算

| 项 | 时长 |
|:--|:--|
| 单局总长 | **900 秒** |
| 战斗 | 约 500 秒 |
| 移动 / 赶路 | 约 160 秒 |
| 决策 / 搜刮 / 破坏物 | 约 100 秒 |
| 撤离追逐 | 约 140 秒 |

### 10.2 三段式节奏

| 时间 | 阶段 | 玩家在做 | 系统在推 |
|:--|:--|:--|:--|
| 0:00–4:00 | **探索** | 定路线、看地形、打第一波 | 低密度怪、出生点分散、无强制战斗 |
| 4:00–11:00 | **交战** | 抢事件、打精英、打可破坏物 | **7–8 分钟高价值事件刷新**（声音 + 光效提示） |
| 11:00–15:00 | **撤离** | 往传送门跑，可能被追 | 传送门开启、怪向传送门聚集 |

> **7–8 分钟的事件刷新是每局的情绪高点**：逼玩家做"抢或收手"的决定。

### 10.3 战斗节点

一局 900 秒只够 **4–5 个节点**（每个含接近、拉怪、清场、破坏、拾取，100–140 秒）。

> **一局只能让玩家记住 3 件事** —— 节点必须有"记忆点"，不能是均匀的怪群。

**节点 = 三个选择**：

| 维度 | 选项 |
|:--|:--|
| 入口 | 正面打（快、伤）/ 绕后（慢、安全）/ 打穿可破坏墙（花时间，造新路线） |
| 层次 | 小怪（资源）、精英（威胁）、可破坏物（收益）空间交错，玩家自选顺序 |
| 出口 | 清干净（时间成本）/ 拿完就走（留怪在背后）/ 主动拉怪到别处（战术撤退） |

### 10.4 怪物角色（组合 > 单体）

| 角色 | 作用 | 设计要点 |
|:--|:--|:--|
| 填线 | 资源与节奏 | 多、脆，2–3 刀死，负责"爽" |
| 压制（远程） | 破坏站位 | 逼玩家移动、打断打可破坏物 |
| 威胁（精英） | 必须用技能应对 | 高伤 + 明显起手，可被招架 |
| 控制 | 限制行动 | 逼玩家优先处理 |
| 支援 | 给其他怪加 buff | 优先级最高，逼玩家改击杀顺序 |
| 词条（affix） | 随机性 | 火链、冰霜、吸血、狂暴 |

> **组合决定 build 是否有效**：全填线 → AOE 通吃；混支援 + 远程 → 必须点单点爆发。配装才有意义。

> **落地进度（2026-11-18）**：六类里已经有 **3 类**——填线（骷髅剑士）、压制（骷髅弓手）、
> 控制（骷髅法师：沉默 / 石化 / 火球封路），外加剑士的碎骨击（缴械）。精英 / 支援 / 词条怪
> 还没有，`monster_skill.xlsx` 的 `kind` 也已经留好了位置（新的出手形态 = 加一个 `kind`）。

### 10.5 可破坏物（替代"搜容器"）

市面搜打撤的"搜"靠 UI 遮挡制造脆弱时刻（蹲下、视野被挡、不能动），我们**用动作语言替代**：

| 设计 | 说明 |
|:--|:--|
| 高价值可破坏物需要**持续攻击 2–4 秒** | 期间**站桩、不能移动、动作锁死、有挥砍音效** |
| 更高级的需要**特殊动画（更长时间）** | 窗口更长、更响、更值得埋伏 |
| **破坏会惊醒周围的怪** | 玩家必须**先清场再破坏** —— 把静态风险变成动态风险 |
| **最高价值物需要"机关"** | 先点燃 / 击碎护罩 / 打掉守卫，窗口最长 |

> 三个要素（背身、站桩、声音）全齐，偷袭玩法成立，且比"蹲着看进度条"更符合 2.5D 的动作感。

### 10.6 撤离：传送门

**不使用"撤离点"，包装成传送门。** 必须有"撤"的过程。

**状态机**

```
关闭 ──(拉闸 / 时间事件)──→ 已激活 ──(玩家引导 8–12s)──→ 开启 ──(1 人撤离)──→ 已激活
                               ↑                                              │
                               └──────────── 次数耗尽 ──→ 关闭 ←──────────────┘
```

**规则**

| 项 | 规则 |
|:--|:--|
| 开启方式 | 玩家**引导 8–12 秒**（可视为引导技能），分 3 段进度（每段有音效/光效）。**实现取 8 秒下限**：站桩越久越像罚站，撤应该利索 |
| 打断 | **打断只清空进度，不加硬直**（v4 去掉了原 3 秒硬直：清空进度本身已经是足够的惩罚） |
| 撤离 | 开启后撤离是**瞬间**的 |
| 开启次数 | 每扇门有固定次数（例：3 次），**每次只允许 1 人撤离**，用完后进入关闭 |
| 关闭后 | 永久关闭（次数耗尽） |
| 数量关系 | **门数量 > 同时在场玩家数**（例：5 扇门 / 3 人），制造抢门压力但不制造"必死"。**具体数字与同场人数对齐**：人数变，门数与开启次数跟着变 |
| 广播事件 | 可做"拉闸"：拉闸后 1 分钟，某处传送门开启 + **全图广播**（把开门变成公开事件，制造埋伏窗口） |

**为什么不需要"开门者优先通行权"**：开门者天然离门最近，且撤离是瞬间的 —— 他不会被自己开的门坑到（除非被控住，那是玩法，不是漏洞）。

> **组队时**：一人开门、三人走的问题后议（可能做群体传送门）。当前只做单人。

## 11. 地图

| 项 | 决定 |
|:--|:--|
| 规模 | **比现有 128×96 大得多**，分区域 |
| 结构 | **环形**（A→B→C→A），多个出入口，便于绕后 / 甩追 / 换路线 |
| 分区 | 4–5 个区域，每区 2 条以上出入通道 |
| 功能 | 需要**大地图查看**功能 |
| 复用 | PVE 副本与 PVPVE **共用**同一套地图（信息优势是设计意图） |

> 15 分钟一局只走**一条路线**（约 1/3 张图），其余区域留给别的路线 / 别的局。

### 11.1 落地（2026-11-18 重做）

用户当时提了三条，改法逐条对应：

| 反馈 | 改法 |
|:--|:--|
| 四块太规整、区内也太规整（等距柱阵 / 四四方方一大面墙） | 每区是一块**手工多边形**地块（`arena_layout.OUTLINE` → 扫描线填充 + 边界 fbm 抖动 ±8 格）→ 半岛 / 凹湾 / 斜切角，地块外是 VOID。区内墙不再是柱阵：院墙按 5–9 格一段抖动、院子之间用**带门的连接墙**串成一片 |
| 区块之间像大平原 | 区与区留 **40–80 格 VOID 带**，只靠 **8 条带墙走廊**（宽 7 格、有转折）连通；每对相邻区 2 条（`CORRIDORS` 声明，`verify()` + 单测双保险） |
| 图太小（1 分钟走完） | **720×448 格 = 23040×14336 px**（旧图 7.9 倍面积）。实测：东西横穿 BFS **99 秒**，从出生点到最远点 **150 秒**（`preview_map.py` 量的，不是估的） |

四套**地形语言**（是阻碍方式，不是美术风格）：

- **院落**：16 个尺寸不一的院子错位咬合 + 带门连接墙 + 院内假山 → 卡门 / 绕后 / 被堵死
- **东廊**：整区先填满岩体再挖 —— 一条**蛇形**主廊来回折返 + 15 条梳齿支廊 + 18 根贴边廊柱 → 横穿必须来回走
- **石窟**：fbm 岩体 + 蜿蜒洞道 + 大石柱（阈值自适应保证主连通块 ≥80%）→ 没有一条长直边
- **水榭**：不规则湖 + 三座桥 + 池心亭 → 桥是唯一咽喉

配套改动：分区归属从「矩形铺满」改成**逐格光栅 `zoneGrid`**（`zones` 的矩形降级为包围盒，
只用于标签位置与粗筛）；A* 缓冲改成「一次分配 + 世代标记」（32 万格每次 `new Float64Array`
会让连点卡顿）；大地图不再按矩形描边，改为按 `zoneGrid` 涂**不规则色块**。
出生点周围留 36 格（≈1150px）不放怪 —— 开局要有观察窗口。

### 11.2 第二轮（2026-11-18 晚）：第五区「宝库」+ 视野

用户第二轮给了五条，逐条对应：

| 反馈 | 改法 |
|:--|:--|
| 右上与右下**画了路却走不通** | 根因是**构建顺序**：先挖走廊、再建各区，而东廊/石窟是"整区填满墙"的地形，把走廊中段重填成 WALL —— 图上还留着路的样子。现在 `build_terrain()` 是 land → 各区 → **走廊最后挖**，且走廊端点会被吸附到**区内主连通块**（`_zone_main_block`），不会再停在墙里的一小块空地上。实测五区全部从出生点可达（127993 / 130595 可走格） |
| 中间加一块**高价值战利品区**，四区各一条路通向它 | 新增第五区 **`vault` 宝库**（350–490 × 244–346 格）。四块地块各外移 120 格让出天井，图扩到 **840×544 = 26880×17408**。宝库是唯一"填满再挖"的**库房群**：9 间房 + 3 格门洞 + 货架，怪 20 只 / 可破坏物 22 个（密度是四区的 5–6 倍），且只出匣与舍利匣（不出破木箱） |
| 小地图别显示整张图，只显示以自己为中心的一小部分 | `drawMinimap` 重写成**跟随玩家的局部窗口**：窗口格数由视野半径决定（`rows = 视野格 × 2.05`），只画窗口内的墙 / 虚空，玩家永远在中心。想看全图只能按 `M` |
| 小地图与大地图只显示玩家和传送门 | 两处都删掉怪物、可破坏物、事件光柱、掉落。大地图图例从 6 项降到 4 项（你 / 传送门 / 墙 / 虚空） |
| 战争迷雾 + 视野半径可配置 | `combat/fog.ts`：`state.visionRadius`（默认 **16 格 = 512px**，夹在 8–120 格）是唯一来源，天赋 / buff / debuff 直接改它。**可见度按世界格存**（`FogField.shade`）：逐格 `lineOfSight()` 走格遍历、**终点格不检查** → 墙自己亮、墙后第一格就暗（阴影贴墙），擦角两侧都要求通畅（不漏光）；每格按 `dt` 向目标逼近 —— **丢失视野 0.6 秒暗下去、新探索 0.22 秒亮起来**，不是一帧切换。射线原点取玩家**所在格的中心**，玩家格内挪动时整张表逐格不变（零抖动）。渲染：格 → 5 次项卷积 → 子格双线性 → 按世界格对齐的离屏位图（4px/格）→ 只把屏幕内那块放大上屏，`FOG_MAX_SHADE = 0.56`。**看不见的是东西，不是地方**：怪 / 箱 / 门 / 掉落 / 弹道按 `inSight` 剔掉，地形照画。**别退回射线多边形**（端点是离散采样，一上屏就是毛刺且随亚像素位置跳） |

指标（`preview_map.py`）：东西横穿 BFS **115 秒 / 23.6k px**，出生点→最远点 **193 秒**；
区内可走率 院落 80.7% / 东廊 45.4% / 石窟 61.4% / 水榭 67.2% / **宝库 67.8%**；
每对相邻区口子 = 2（环形四对）+ 1（四区→宝库）。
