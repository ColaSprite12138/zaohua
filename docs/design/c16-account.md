## 16. 账号与存档（自建，2026-11-20）

> 这一章不在原始设计里，是查清平台能力后补的。**动存档、交易行、联机之前先读这一节**，
> 否则会重复踩「以为平台给了云存档」的坑。

### 16.1 为什么自建

造化平台的存档分三层，游戏侧只有最弱的一层可用（2026-11-20 实查）：

| 层 | 是什么 | 游戏能不能用 |
|:--|:--|:--|
| 平台云存档 | `/api/v1/cloud_data`（account + slot），需登录 | ❌ 游戏侧 SDK 里 `cloudData` 出现 **0 次**，没有调用入口 |
| IndexedDB `vibegame_cloud_data` | 平台云存档的本地镜像 | ❌ 游客 `resolveAccountKey()` 返 `null`，整条路径跳过 |
| SDK `storage` | `localStorage['__vag_cloud_data_<key>']` | ⚠️ 只有这一层能用，但**没有 userId 命名空间** |

并且**未登录游客拿不到宿主身份**：实测 13 秒内 0 条 host→game 消息，`whoami` 返 401，
`user.getCurrent()` 兜底成 `roomKey`（`__game_builder_room_key__` 里的随机 UUID）——
**这是设备级伪身份，换浏览器就变**。所以「玩家云存档」只能自己做。

### 16.2 身份模型：只有两种，游客不落库

| | 账号（`kind='password'`） | 游客 |
|:--|:--|:--|
| 存在哪 | 云服务器（香港 CVM） | **只在浏览器** `localStorage` |
| 服务器有没有行 | 有 | **一行都不建**（2026-11-20 起） |
| 换设备 / 清缓存 | 能找回 | **找不回**，且无删除入口（本来就没数据） |
| 设备密钥 | 无 | 无 |

**为什么游客不进服务器**：游客清缓存后私钥就没了，那行 `accounts` 永远没人能登、也没人能删，
孤儿数据会线性增长（一次端到端验证就留下 5 行）。现在游客走 `forgeax.save.guest.v1` 本地存档，
**不发任何网络请求**（验收断言：请求数 = 0）。

**注册是唯一门槛，且没有身份门槛**：一次 `POST /auth/account/register`，只要用户名 + 口令。
没有公钥、没有签名、没有 nonce、没有设备绑定。同一浏览器连注册十个号也不会被拦。

### 16.3 服务端存什么（`accounts` 全部 8 列）

| 列 | 内容 |
|:--|:--|
| `user_id` | 随机 `u` + 16 hex（**与设备无关**，不是公钥哈希） |
| `username` / `username_lc` | 玩家输入的用户名 + 小写副本（唯一索引与登录用） |
| `password_hash` | `scrypt$16384$8$1$<16B 盐>$<哈希>`，单向不可还原 |
| `display` | 昵称（= 用户名） |
| `created_at` / `banned` / `kind` | 时间 / 封禁位 / 类型 |

**明确不存的**：设备公钥、IP、UA、浏览器指纹、屏幕尺寸、手机号、邮箱、身份证。
IP 只在登录限流的进程内 `Map` 里活 15 分钟，**从不落库**；日志只有
`method / path / status / userId`，**不打请求体**。

> 2026-11-20 已删除并建表迁移：`device_keys`（设备公钥）、`challenges`（签名 nonce），
> 路由 `/auth/register`、`/auth/challenge`、`/auth/verify`、`/auth/pubkey-challenge`、
> `/auth/account/upgrade` 全部下线（现 404）。

### 16.4 口令与登录

- **scrypt** N=16384 / r=8 / p=1，16 字节随机盐，`timingSafeEqual` 比较
- 用户不存在也跑一次**假 scrypt**（堵时间侧信道）
- 账号不存在 / 口令错误，措辞完全一致，一律 `401 bad_credentials`
- 限流两个维度同时生效：`ip|username` 10 次、`username` 30 次 / 15 分钟
- 校验只有格式：用户名 2–20 字（中英文数字下划线短横线），口令 8–72 位且不等于用户名

### 16.5 云存档

- 主键 `(user_id, slot)`，`slot` 匹配 `[A-Za-z0-9_-]{1,32}`，每人 **20 槽**，单份 **≤256KB**
- **`rev` 乐观锁**：写入带 `baseRev`，不匹配返 `409 save_conflict`，客户端拉新 rev 重试（**不覆盖**）
- 可枚举（`GET /saves`）、可单删（`DELETE /save/:slot`）
- 客户端 `assets/meta/save-client.ts`：400ms 节流 + 失败计数；**首写不 apply 空档**
  （云端 `rev=0` 但界面已有进度时，先 `captureEnvelope()` 上传再挂载）
- 读写时机：**只在局外**（`!inRun`）。局内刷新不落盘 —— 设计如此（避免死亡后复活拿回东西）

### 16.6 开局门禁

登录面板是 `<body>` 第一个子元素，`position:fixed; inset:0; z-index:40`，自带不透明背景。
登录 / 注册 / 游客三选一，**进入前看不到商店、背包、装备栏**。有会话也只显示
「上次身份 + 继续进入」，**不自动跳过**（自动跳过会让玩家换号时找不到入口）。

游客 → 注册时**迁移本地存档**：云端空档 + 本机有 `forgeax.save.guest.v1` → 上传 → 删本地副本
（不留双份，否则退回游客会看到一份旧进度）。

### 16.7 合规边界（PIPL）

**已达标**：只收用户名 + 口令哈希（最小必要，且因此**不触发**实名核验与手机号相关义务）；
scrypt 单向存储；HTTPS 全链路；服务只监听 `127.0.0.1` 由 Caddy 反代；库内数据无法关联到自然人。
