## 0. 这批设计的共同签名

用户 2026-11-23 提的这批技能不是零散的例子，它们共享同两个偏好。建议把它固化成判据，
以后每个新技能都先过这两条，否则会越加越像数值堆：

**判据 1 · 可读的预警（telegraph）**
高伤害技能必须先给对手反应窗口：剑贯长虹先画固定轨迹再出刀、焚天先缩圈再落火、
封疆是一面看得见的墙。**不允许"点下去就掉血"的爆发。**

**判据 2 · 可见的承诺（commitment）**
高收益必须先付代价，且代价看得见：剑贯长虹起手锁身、剑势如虹期间拿不到势、
焚天读条会被打断。**不允许"零风险的高收益"。**

> 这两条合起来 = 「信息透明 + 时机博弈」，而不是「数值碾压」。它同时也是 PVP 平衡的护栏：
> 只要预警够清楚，输的一方总能说出"我该往哪躲"，而不是"我装备差"。

## 1. 系统层：势（重甲专属资源）

### 1.1 定位

**势是重甲专精的固有资源，不是星图节点。** 点亮任意 2 个重甲节点（专精点 ≥ 2）后自动获得势条。

**这推翻了 `game-design.md` 8.3 的「没有流派专属资源」**，必须显式记账。8.3 原来给的理由是：

> 星图是所有人共用的，专属资源放前面则人人都有，放后面则前期没有，都不成立。

这个理由在当时的模型下成立（只有"一个角色 + 一张共用星图"）。现在不成立了，因为上一轮引入了
**专精点**：重甲身份已经有一个结构载体（专精累计门槛 + 长剑武器门槛），所以势可以挂在"专精"上，
而不是挂在"角色"上。既不会人人都有，也不会前期没有。

> **需要用户确认这一条**：它是已定条款的推翻，不是新增条款。

### 1.2 规则（初值）

| 项 | 规则 | 理由 |
|:--|:--|:--|
| 来源 | **近战普攻命中 +1；近战技能命中 +1** | 法术/远程不产势，势只属于贴脸的人 |
| AOE 限制 | 一次技能命中多个目标**只 +1**（`sweep` 转一圈打 5 只也是 +1） | 否则横扫清杂兵瞬间满层，节奏全崩 |
| 上限 | 6 层 | 与"6 秒爆发窗口"对齐，好读 |
| 每层收益 | **+2% 伤害、+1% 移速**（满 6 = +12% / +6%） | 小、可叠、越打越敢贴脸 |
| 衰减 | 最后一次命中后 **5 秒无命中** → 每 0.5 秒 −1 层（6 层清空需 3 秒） | 5 秒硬清零太脆（清完一波走两步就归零）；渐进衰减给"冲下一波"的窗口 |
| 清零时机 | 死亡、撤离、换局 | — |
| 不可获得期 | 剑势如虹生效中 + 结束后 1.5 秒 | 见 2.3 |

### 1.3 为什么要"5 秒衰减"而不是"永久保留"

永久保留会让最优解变成"攒满 6 层然后绕圈等 CD"，重甲从"前排持续输出"退化成"马拉松"。
衰减把势变成**必须用进攻维持的东西**，正好对上 9.1 里重甲的定位（前排 / 持续）。

### 1.4 可见性（8.8 硬要求）

- HUD 血条下方 6 格 pips，满层变金色。
- 满层时武器描边发光（体素上直接改材质，和燃烧/冰冻同一套手法）。
- 衰减中 pips 逐格熄灭，**不能只有数字**。

### 1.5 实现成本（中）

- `state.ts` 加 `momentum: number` + `momentumExpireTick`（或 `lastHitTick`），**进 `SHARED_KEYS` 和 hash**。
- 现有 `status.ts` 是"给目标上 debuff"的模型，**没有自我叠层资源**；不要硬塞进 status 表，
  单独一个 `momentum.ts` 更干净（产出 = 层数，注入 = `modifiers.ts` 的伤害/移速乘区）。
- 衰减必须按 tick 判定，禁用 `Date.now`（`check-determinism.mjs` 会拦）。

### 1.6 风险：滚雪球

势是正反馈（越打越强），在 PVP 里会让优势方更优势。天然的缓解已经在规则里：
**命中玩家 +1、命中怪物 +1，但 PVE 里怪多，攒势快** —— 于是"打怪攒满再去打人"是有意义的操作，
而不是"打赢的人永远满层"。若要再压，把"命中玩家"改成 +1、"命中怪物"上限 3 层。

## 2. 六个技能

### 2.1 焚天（主动 · 火 × 法术 × 法杖）

| 项 | 值 |
|:--|:--|
| 形态 | 读条 1.2s（可被打断）→ 光标处半径 160 的火柱落下 |
| 预警 | 落点提前 **0.9s** 出现收缩警示圈（外圈缩到内圈 = 命中瞬间） |
| 伤害 | 110 + 点燃 3.5s；落点留下半径 120、3s 的火海（DOT） |
| 消耗 | 30 蓝 / CD 20s |
| 不做 | **不击退**（击退留给「斥」，重复了就没法分工） |

**定位**：法术的"大招 / 封地"。它和火墙、冰墙构成同一族——**不是打人，是改变"哪里能站"**。

### 2.2 势（被动系统 · 重甲）

见第 1 节。它是系统，不是技能节点。

### 2.3 剑势如虹（主动 · 火 × 重甲 × 长剑）—— 普攻流

| 项 | 值 |
|:--|:--|
| 消耗 | **全部势**（至少 1 层才能发动） |
| 持续 | **层数 × 1.0 秒**（1 层 1 秒，6 层 6 秒） |
| 增益 | 攻速 +40%（`attackMul 0.7`）、近战距离 +30%、伤害 +25% |
| 封印 | 生效中 **无法获得势**；结束后再锁 1.5 秒 |
| 蓝 / CD | 0 蓝 / CD 18s |

**为什么"持续 = 层数 × 1s"而不是固定 6 秒**：让"押几层"变成玩家的每一次决策。
3 层换 3 秒是保命式兑现，6 层换 6 秒是赌命式兑现。固定时长会让它退化成"满层才按"的单一按钮。

**实现成本（中）**：攻速可以直接复用 `status.attackMul`（已有）；但"近战距离 +30%"是
**技能级临时乘区**，现在只有星图给 `range_px`，需要在 `modifiers.ts` 之外加一个 runtime 加成入口，
否则要和星图混在一起算。这一点要单独确认。

### 2.4 剑贯长虹（主动 · 风 × 重甲 × 长剑）—— 技能流

| 阶段 | 时间 | 内容 |
|:--|:--|:--|
| 起手 | 0 – 0.35s | **身体锁定**（不可移动、不可取消），同时地面画出固定轨迹：长 420px、宽 70px 的走廊 |
| 第一段 | 0.35s | 瞬发剑气，走廊内命中：40 伤害 + 硬直 0.45s（`stagger`） |
| 第二段 | 1.05s | 同走廊再斩：140 伤害 |
| 可选兑现 | 若有 ≥3 层势 | 花 3 层：第二段变"贯穿"（无视格挡 / 不被地形打断），且第二段提前 0.2s |
| 蓝 / CD | 20 蓝 / CD 12s |

**关键设计点**：轨迹**先出现，刀后到**。这让 PVP 里"看见轨迹 → 侧移 → 白嫖对方 1 秒硬直"
成为可执行的操作，也让"故意空放逼对方走位"成为进攻手段。

**`stagger`（硬直）要新开一个状态**，不能复用 `stun`：
`noMove + noAttack + noSkill`，但 **`noDodge=false`** —— 被砍中的人还能闪避取消，才守得住
"所有硬控必须可反制"这条红线（8.4 里晕眩标注的是"无解，但时长 ≤1.5s"；硬直不该走到那一步）。

**实现成本（中高）**：现有 `SkillDef` 是**单段**（一次 `cast_time` + 一次结算），
这个技能需要 `stages[]` + 前摇锁定 + 轨迹渲染。建议加一个新的 `SkillKind = 'thrust'`，
而不是把 `bolt` 改成万能的。

### 2.5 封疆（主动 · 冰 × 法术 × 法杖）—— 原名「冰墙」

**命名**：`封疆`（首选）—— 封 = 阻断，疆 = 战场边界，正好是"分割战场"这四个字。
备选：`冰阙`（阙 = 关隘，更冷峻）、`寒关`（更直白）。三个都比"冰墙"更贴你其他技能的味道。

| 项 | 值 |
|:--|:--|
| 形态 | 长 220px、厚 28px 的墙，**不可破坏**，存在 4.5s |
| 限制 | 同一施法者同时只能有 **1 面** |
| 战术作用 | **阻断弹道**（火球 / 箭）—— 这才是它真正的价值，不是挡路 |
| 蓝 / CD | 22 蓝 / CD 14s |

**搭配**：封疆 + 焚天 = 把对手关进火里。这是法师的"筑界"连招，也是这批技能里唯一的
**技能 × 技能协同**（其余都是单点）。协同比数值更能让人记住一个流派。

**实现成本（高，建议放下一批）**：动态障碍要同时动三个地方——
`movement.canStand()`、弹道碰撞、以及怪物寻路（nav 网格要标脏）。
另外两个 PVP 死锁风险必须提前写死：① 不许封住撤离门 / 唯一通道（地图侧约束）；
② 生成时若把玩家夹住，把玩家推到最近可站立格。

### 2.6 斥（主动 · 法术 · **无武器要求**）—— 保命

**命名**：`斥`（首选，与「势」对仗，单字很硬）。备选：`环斥`、`退散`。

| 项 | 值 |
|:--|:--|
| 形态 | 以自身为圆心 120px，把范围内敌人沿"远离自己"的方向推 **90px** + `stagger` 0.35s |
| 伤害 | 8（几乎为零，**它是脱离，不是攻击**） |
| 蓝 / CD | 18 蓝 / **CD 16s** |
| 不做 | **不做地形杀**：只在本层可站立范围内推，遇边缘/墙即停 |

**为什么明令禁止地形杀**：设计 9.3 把"推击 = 地形杀执行者"给了重甲。如果法师的保命技也能把人
推下高台，它就不是保命技，是零成本处决，而且和重甲的定位撞车。

**保命技不绑武器** —— 这条要写成通则：位移与保命技能一律不设装备门槛，
否则"武器掉了 = 连跑都跑不了"，和 9.4「耗尽 = 罚站 = 必须避免」直接冲突。

## 4. 建议实现顺序（按成本从低到高）

| 顺序 | 内容 | 要动的模块 | 量级 |
|:--|:--|:--|:--|
| 1 | **焚天** | `skill.xlsx` + 复用 `strike` + 落点 `zone` | 低（几乎纯数据） |
| 2 | **势 + 剑势如虹** | 新 `momentum.ts` + `state` + hash + HUD pips + runtime range 乘区 | 中 |
| 3 | **斥** | `movement.ts` 反向位移 + `stagger` 状态 | 中 |
| 4 | **剑贯长虹** | `SkillKind='thrust'` + `stages[]` + 轨迹渲 | 中高 |
| 5 | **封疆** | 动态障碍（movement / 弹道 / nav 三处） | 高，建议下一批 |

第 1 步能最快看到东西，第 2 步决定"重甲"这个流派成不成立，建议先做这两步。
