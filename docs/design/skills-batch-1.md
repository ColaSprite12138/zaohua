## 0. 这批设计的共同签名

这批技能共享同两个偏好。建议固化成判据，以后每个新技能先过这两关：

**判据 1 · 可读的预警（telegraph）**
高伤害技能必须先给对手反应窗口：剑贯长虹先画固定轨迹再出刀、焚天先缩圈再落火、
封疆是一面看得见的墙。**不允许"点下去就掉血"的爆发。**

**判据 2 · 可见的承诺（commitment）**
高收益必须先付代价，且代价看得见：剑贯长虹起手锁身、剑势如虹期间拿不到势、
焚天读条会被打断。**不允许"零风险的高收益"。**

> 合起来 = 「信息透明 + 时机博弈」，不是「数值碾压」。它也是 PVP 平衡的护栏：
> 只要预警够清楚，输的一方总能说出"我该往哪躲"，而不是"我装备差"。

## 1. 一个 build 一个终极（2026-11-24 第四次修订）

> 本轮两处改动：① **数量排他改成「终极节点全局互斥」**（一条 canPick 判断）；
> ② **不加金 / 土新色**，现有的火 / 风就够表达"两支"。

### 1.1 硬规则：终极节点全局互斥

| 项 | 规则 |
|:--|:--|
| 星图 | `kind = 'ult'` 的节点**全局最多点亮 1 个**；已有终极时，其余终极在 `canPick` 直接拒绝 |
| 拒绝文案 | 「终极技能只能带一个」+ 高亮已选的那个 —— **不许只说"不可用"** |
| 技能栏 | **不改**。7 格照旧，终极就占一个普通格 |
| 数据 | `starmap.xlsx` 加一个 `kind='ult'` 的取值即可，**不需要 `exclusive_group`、不需要按线分组** |

**为什么不做"终极技能栏"**：既然拒绝发生在星图上（点不了第二个），技能栏永远不会出现
第二个终极，专属格子就只是装饰 —— 多一套 UI 状态、多一处要维护的边框和空位表现，收益为零。
**一个 canPick 判断就够了，不要为它再造一个 UI 概念。**

### 1.2 为什么放弃"用点数 / 色门拦数量"

前面三版都试过，全不成立：

| 办法 | 问题 |
|:--|:--|
| 把价格抬到算不出来（双终极 > 20 点） | 点数是会变的（以后加探索点就破），而且玩家算不明白"为什么差 1 点" |
| 颜色链 + `exclusive_group` | 色门只挡"方向"（势产火不产风），挡不住"两种颜色都攒"的人 —— 实测双终极约 16 点就点得出来 |
| 终极技能栏（专属格） | 和"星图上不可点"完全等价，只是多一层 UI |

**终极互斥是一条规则、一眼看懂、与点数完全解耦。** 它还允许终极变便宜（3–4 点），
把预算从"凑够 11 点"里释放出来，去做真正的取舍：广度和深度，而不是被一个大招榨干。

> 顺带删掉上一版为数量排他准备的两个重量级测试（"两终极成本之和 > 总点数"、整体可达性搜索），
> 以及"终极格"那套 UI 改动。它们解决的都是错误的问题：
> **能用一个判断解决的事，不要用搜索或新概念去证。**

### 1.3 亲和门剩下的两件事

去掉数量排他之后，亲和的任务变纯了，只有两件：

| 任务 | 说明 |
|:--|:--|
| 星座开锁 | 原有规则，不动 |
| **决定"为了这个终极，你得先吃什么属性"** | 这才是第一轮要的"前置点数"，它被颜色顺带实现了 |

于是**不管谁去拿，同一个终极都是同一条属性路径**：想开剑势如虹就得吃火（伤害 + 生命），
想开剑贯长虹就得吃风（距离 + 移速）。不需要 per-skill 前置表。

还剩一条必须写死的数据规则：

> **机制节点的产出色 = 它专属终极的需求色，且不得产出另一个终极的需求色。**
> 例：势产火、不产风。

它不再是"数量排他"的唯一保障（那是终极格的活），但它仍然保证**方向的味道不串** ——
否则「势」顺手给 1 点风，剑势如虹的 build 就会莫名其妙地朝突刺方向长。
这条必须是 `starmap-data.test.ts` 里的断言，不是设计备注。

### 1.4 不需要加金 / 土：现有的火 / 风就是这组对立

你说金 / 土只是举例 —— 同意，而且**不用加色**。现有 6 色里已经有"爆发 ↔ 机动"这组对立：

| 支 | 亲和需求 | 玩法味道 | 现有节点已经覆盖 |
|:--|:--|:--|:--|
| 剑势如虹 | **火 ≥ 5** | 爆发 / 越打越猛 | 燎原 +伤害、**炭壳 +6% 生命**、火墙 |
| 剑贯长虹 | **风 ≥ 5** | 机动 / 找窗口 | 冲锋、疾行 +近战距离、割裂 |

**"想开剑势如虹就得变肉"这条仍然成立** —— 因为余烬星座里本来就有「炭壳 +6% 生命」。
**防御的味道不需要一个土色，它已经是火星座的属性配方之一。**

省下来的东西：不新增列、不拆 `ElementId` / `AffinityColor`、不扩星座数量、不改 UI、不重写护栏。

> 阈值 5 是初值：现有 24 个节点每个产 1–2 点亲和，≥5 大约要 3 个节点。按真表算一遍再定。
> 真需要"纯防御"这种新味道时再加土不迟，现在没有这个需求。

### 1.5 平衡护栏：爆发色只给续航，不给硬减伤

允许：生命上限、护盾、生命 / 护盾回复速率、受击回蓝。
禁止：`damageTakenMul < 1`（直接减伤）、免控、无敌帧这类**生存硬减伤**。

理由：势是"越打越强"的正反馈，再叠一层硬减伤，剑士就变成"打不死且越打越强"，
在 PVP 里就是滚雪球的终点。**用"扛得久"换"打得久"，不能用"打不动"换。**

### 1.6 20 点怎么花

| 归属 | 点数 | 内容 |
|:--|:--|:--|
| 终极本身 | 3–4 | 一个终极（格子已经限死，可以便宜） |
| 它的属性前置 | 3–5 | 满足亲和的最短路径（火 ≥5 / 风 ≥5） |
| 线上补强 | 4–6 | 普通主动 + 属性 / 大点 |
| 跨色定制 | 5–7 | 低阶节点，谁都能点 |
| 合计 | ~20 | 主动 4–5 个 + 1 个终极 |

> "只够一个终极"现在由**互斥**保证，点数只负责广度 —— 所以预算可以松一点。
> 这是把约束从"数学"挪到"规则"换来的好处：不再需要精确算到"差一点就点不出来"。

### 1.7 一个直接后果：纯被动 build 正式不成立

上一轮我建议"做 4 个触发型大点，让少技能多被动成为一种玩法"。**在新经济下这条可以砍掉**：

- 预算强制一个终极，而终极全是主动技能 → 纯被动流拿不到战力天花板；
- 所以被动只能是调味，不必承担"撑起一条流派"的责任。

省下来的工作量可以直接投到终极技能上。这是"只点一个终极"这条约束的意外红利。

## 2. 势：一个节点，不是系统特权

### 2.1 定位（2026-11-23 口径修正）

**势不是重甲专属。任何玩家，不管流派、不管武器，点出「势」这个被动节点就能触发。**
它是**火系**的机制节点，门槛 **火亲和 ≥ 2**，产出**火 2 + 水 1**，作用是引入"命中攒层"这个玩法动作。

**为什么不能放在线首（门槛 0）**：那样 1 点就能把四条线的机制全点出来，身份不排他，
而且玩家在 1–3 级、还不知道自己在玩什么的时候就被要求宣告立场。挂在"火 ≥ 2"上，
拿到它的成本是"先吃两个火系节点"，这时玩家已经摸过这条线的手感了；
而且它产出**火**，天然把你推向"爆发 + 生命"那一侧，而不是随便给一个万能入口。

但**只点「势」不点终极，仍然是明确的亏本**：势单独只给很少的属性（见 2.3），它的全部价值
在「剑势如虹 / 剑贯长虹」上。加上它前面的两个火系节点，停在这里等于沉没 3 点，
所以 2.6 的"看得见"要求是硬性。这是**有意为之的取舍**，不是设计失误。

### 2.2 8.3 的修订方式

`game-design.md` 8.3 写的是「**没有流派专属资源**」，理由是"放前面则人人都有，放后面则前期没有"。

这个理由在"资源挂在角色 / 专精上"时成立，但**在"资源挂在可点选的节点上"时不成立** ——
因为它是 opt-in 的：既不人人都有，也不会前期没有（你得先攒 2 点火，再花 1 点拿它）。

所以 8.3 不需要推翻，只需要**收窄**成：

> **没有与生俱来的流派资源。** 流派资源必须是**可点选、可放弃的节点**，且放在线上而非角色上。

这比原来的"一律不做"更准确，也没有开一个"以后每个流派都塞专属资源"的口子。

### 2.3 规则（初值）

| 项 | 规则 | 理由 |
|:--|:--|:--|
| 来源 | 近战普攻命中 +1；近战技能命中 +1 | 法术/远程不产势，势只属于贴脸的人 |
| AOE 限制 | 一次技能命中多个目标**只 +1** | 否则横扫清杂兵瞬间满层，节奏全崩 |
| 上限 | 6 层 | 与"6 秒爆发窗口"对齐，好读 |
| 每层收益 | **+1% 伤害**（满 6 = +6%） | 刻意做小：约等于一个 1 点属性节点，这样"只点势不点终极"才真的是亏本 |
| 衰减 | 最后一次命中后 **5 秒无命中** → 每 0.5 秒 −1 层（清空需 3 秒） | 5 秒硬清零太脆；渐进衰减给"冲下一波"的窗口 |
| 清零 | 死亡、撤离、换局 | — |
| 不可获得期 | 剑势如虹生效中 + 结束后 1.5 秒 | 见 3.2 |

**为什么衰减不能取消**：永久保留会让最优解变成"攒满 6 层绕圈等 CD"，重甲从"前排持续输出"
退化成"马拉松"。衰减把势变成**必须用进攻维持的东西**。

### 2.4 可见性（8.8 硬要求）

- HUD 血条下方 6 格 pips，满层变金色；衰减时逐格熄灭，**不能只有数字**。
- 满层时武器描边发光（和燃烧 / 冰冻同一套体素手法）。

### 2.5 实现成本（中）

- `state.ts` 加 `momentum` + `lastHitTick`，**进 `SHARED_KEYS` 和 hash**。
- 现有 `status.ts` 是"给目标上 debuff"的模型，**没有自我叠层资源**；不要硬塞进 status 表，
  单独 `momentum.ts` 更干净（产出层数，注入 `modifiers.ts` 的伤害乘区）。
- 衰减按 tick 判定，禁用 `Date.now`（`check-determinism.mjs` 会拦）。
- **节点是否已点是门槛**：势的功能由"是否点亮 `node:momentum`"开关，不是靠专精，纯读 picks。
- **亲和早已是派生值**：`affinityOf()` 累加已点节点的 `aff_<color>`，零新字段，
  `sanitizeProgress` 顺序重放天然兼容 —— 这也是这一版比"线内投入门槛"省事的原因（见 1.2）。

### 2.6 亏本必须看得见

"只点势不点终极 = 亏本"可以接受（玩家自己选的），但**不能是隐形的坑**。要求：

- 节点卡片直接写「需要「剑势如虹」或「剑贯长虹」才有收益」；
- 火不够 2 点时，势显示「还需火亲和 N 点」，不是干脆看不见；
- 点了势、但火不够 5 点时，「剑势如虹」显示「还差 N 点火亲和」而不是干脆灰掉。

## 3. 技能明细

### 3.1 焚天（终极 · 火 × 法术 × 法杖）

| 项 | 值 |
|:--|:--|
| 形态 | 读条 1.2s（可被打断）→ 光标处半径 160 的火柱落下 |
| 预警 | 落点提前 **0.9s** 出现收缩警示圈（外圈缩到内圈 = 命中瞬间） |
| 伤害 | 110 + 点燃 3.5s；落点留半径 120、3s 的火海（DOT） |
| 消耗 | 30 蓝 / CD 20s |
| 不做 | **不击退**（击退留给「斥」，重复了就没法分工） |

**定位**：法术线的终极，但它的强度不在伤害，在于**把一片区域变成"不能站的地方"**。
它和火墙、封疆是同一族——不直接打人，改变地形。

### 3.2 剑势如虹（终极 · 火 × 战士 × 长剑）—— 普攻流

| 项 | 值 |
|:--|:--|
| 消耗 | **全部势**（至少 1 层才能发动） |
| 持续 | **层数 × 1.0 秒**（1 层 1 秒，6 层 6 秒） |
| 增益 | 攻速 +40%（`attackMul 0.7`）、近战距离 +30%、伤害 +25% |
| 封印 | 生效中**无法获得势**；结束后再锁 1.5 秒 |
| 蓝 / CD | 0 蓝 / CD 18s |

**为什么"持续 = 层数 × 1s"**：让"押几层"成为每次的决策。3 层换 3 秒是保命式兑现，
6 层换 6 秒是赌命式兑现。固定 6 秒会让它退化成"满层才按"的单一按钮。

**实现（中）**：攻速复用 `status.attackMul`（已有）；但"近战距离 +30%"是**技能级临时乘区**，
现在只有星图给 `range_px`，需要另开一个 runtime 加成入口，不能和星图乘区混算。

### 3.3 剑贯长虹（终极 · 风 × 战士 × 长剑）—— 技能流

| 阶段 | 时间 | 内容 |
|:--|:--|:--|
| 起手 | 0 – 0.35s | **身体锁定**（不可移动、不可取消），同时画出固定轨迹：长 420px、宽 70px 走廊 |
| 第一段 | 0.35s | 瞬发剑气，走廊内命中：40 伤害 + 硬直 0.45s（`stagger`） |
| 第二段 | 1.05s | 同走廊再斩：140 伤害 |
| 兑现 | 若 ≥3 层势 | 花 3 层：第二段变"贯穿"（无视格挡 / 不被地形打断），且提前 0.2s |
| 蓝 / CD | 20 蓝 / CD 12s |

**关键**：轨迹**先出现，刀后到**。PVP 里"看见轨迹 → 侧移 → 白嫖对方 1 秒硬直"是硬操作，
"故意空放逼走位"是进攻手段。

**`stagger` 必须新开状态，不能复用 `stun`**：`noMove + noAttack + noSkill`，
但 **`noDodge=false`** —— 被砍中还能闪避取消，才守得住"所有硬控必须可反制"（8.4）。

**实现（中高）**：现有 `SkillDef` 是单段（一次 `cast_time` + 一次结算），
需要 `stages[]` + 前摇锁定 + 轨迹渲染。建议加新 `SkillKind = 'thrust'`，而不是把 `bolt` 改成万能的。

### 3.4 封疆（普通主动 · 冰 × 法术 × 法杖）—— 原名「冰墙」

**命名**：`封疆`（首选）—— 封 = 阻断，疆 = 战场边界。备选 `冰阙`（阙 = 关隘）、`寒关`。

| 项 | 值 |
|:--|:--|
| 形态 | 长 220px、厚 28px，**不可破坏**，存在 4.5s |
| 限制 | 同一施法者同时只能有 **1 面** |
| 战术作用 | **阻断弹道**（火球 / 箭）—— 这才是它真正的价值，不是挡路 |
| 蓝 / CD | 22 蓝 / CD 14s |

**搭配**：封疆 + 焚天 = 把对手关进火里。这是这批里唯一的**技能 × 技能**协同，
协同比数值更容易让人记住一个流派。

**成本（高，建议下一批）**：动态障碍要同时动三处 —— `movement.canStand()`、弹道碰撞、怪物寻路
（nav 网格标脏）。两个 PVP 死锁必须提前写死：① 不许封住撤离门 / 唯一通道；② 夹住玩家时推到最近可站格。

### 3.5 斥（普通主动 · 法术 · **无武器要求**）—— 保命

**命名**：`斥`（首选，与「势」对仗）。备选 `环斥`、`退散`。

| 项 | 值 |
|:--|:--|
| 形态 | 以自身为圆心 120px，把敌人沿"远离自己"推 **90px** + `stagger` 0.35s |
| 伤害 | 8（几乎为零，**它是脱离，不是攻击**） |
| 蓝 / CD | 18 蓝 / **CD 16s** |
| 不做 | **不做地形杀**：只在本层可站立范围内推，遇边缘 / 墙即停 |

**为什么禁止地形杀**：9.3 把"推击 = 地形杀执行者"给了重甲。法师保命技如果能推人下高台，
它就不是保命技，是零成本处决，还和重甲定位撞车。

**通则**：**位移与保命技能一律不设装备门槛**。否则武器掉了连跑都跑不了，
和 9.4「耗尽 = 罚站 = 必须避免」直接冲突。

## 4. 归属总表

| 技能 | 层级 | 元素 | 亲和需求 | 产出 | 武器 |
|:--|:--|:--|:--|:--|:--|
| 势 | **机制节点** | — | **火 ≥ 2** | 火 2 + **水 1** | **无**（任何武器都能攒） |
| 剑势如虹 | **终极** | —（纯 buff） | **火 ≥ 5** | 火 3 + 水 1 | 长剑 |
| 剑贯长虹 | **终极** | 风 | **风 ≥ 5** | 风 2 + 火 1 | 长剑 |
| 焚天 | **终极** | 火 | 火 ≥ 5 | 火 3 + 水 1 | 法杖 |
| 封疆 | 普通主动 | 冰 | 冰 ≥ 3 | 冰 2 + 水 1 | 法杖 |
| 斥 | 普通主动 | — | —（0） | 水 1 + 风 1 | **无** |

> **结构自检**：势产火，剑势如虹要火 ✔；势**不产风**，所以沿势走下去开不了剑贯长虹 ✔。
> 这就是 1.3 那条数据规则的实际形态。
> ⚠ 但"数量"不归它管 —— 剑势如虹和剑贯长虹**不是互斥关系**，是"终极节点全局只放 1 个"。

> **缺口 1**：目前只有战士方向凑齐 2 个终极、法师 1 个，游侠 / 刺杀 0 个。
> 要跑通"一个终极"，每个方向都得先有 2 个终极可选，否则玩家没得选。

> **缺口 2**：**四个方向的机制节点只设计了「势」一个**。法师（法力过载？读条可移动？）、
> 游侠（标记？鹰眼？）、刺杀（潜行？连击点？）都还没有。机制节点是"身份"的载体，
> 缺了它，那些终极就变成"直接买的大招"，中间少一层节奏。**这个缺口比缺口 1 更卡设计。**

## 5. 实施顺序（按成本从低到高）

| 顺序 | 内容 | 要动的模块 | 量级 |
|:--|:--|:--|:--|
| 1 | **焚天** | `skill.xlsx` + 复用 `strike` + 落点 `zone` | 低（几乎纯数据） |
| 2 | **势 + 剑势如虹** | 新 `momentum.ts` + `state` + hash + HUD pips + runtime range 乘区 | 中 |
| 3 | **斥** | `movement.ts` 反向位移 + `stagger` 状态 | 中 |
| 4 | **剑贯长虹** | `SkillKind='thrust'` + `stages[]` + 轨迹渲 | 中高 |
| 5 | **封疆** | 动态障碍（movement / 弹道 / nav） | 高，下一批 |
| 6 | **终极互斥** | `starmap.xlsx` 加 `kind='ult'`；`canPick` 加"全局只能 1 个" | **低**（纯规则，无 UI） |

第 1 步最快看到东西；第 2 步决定"势"这个循环成不成立；
**第 6 步是这轮设计的骨架**，但它几乎是纯规则改动 —— 这也是换个思路换来的便宜。
