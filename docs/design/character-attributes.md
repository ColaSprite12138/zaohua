## 1. 三层，别混成一张表

| 层 | 内容 | 什么时候变 |
|:--|:--|:--|
| 基础属性 | 力量、智慧、信仰、耐力、意志 | 局外，由装备词条与星图小节点给点数 |
| 派生战斗数值 | 普攻伤害、法术伤害、治疗量、生命上限、法力上限、受伤减免 | 进局时按公式算定 |
| 当前资源 | 生命值、法力值 | 战斗内逐帧变化 |

**生命值 / 法力值是「当前资源」，不是基础属性**；上限才是派生数值。
把三者并列会出现两份真相（当前值和上限谁算属性）。

## 2. 五个基础属性

| 属性 | 决定什么 |
|:--|:--|
| 力量 | 普通攻击伤害 |
| 智慧 | 法术伤害 **+ 法力上限**（两处都由智慧管） |
| 信仰 | 治疗技能的回复量；**红药不受影响** |
| 耐力 | 生命上限 |
| 意志 | 受伤减免 |

属性来源**只有装备词条 + 星图小节点**，**不做升级分配属性点**（等级给的是星点）。

## 3. 公式：只做绝对值加法

```
生命上限 = 基础生命 500 + 耐力点数 × 每点生命
法力上限 = 基础法力 200 + 智慧点数 × 每点法力
普攻伤害 = 武器掷定的固定值 + 力量点数 × 每点物理伤害
法术伤害 = 技能数值   + 智慧点数 × 每点法术伤害
治疗量   = 技能数值   + 信仰点数 × 每点治疗
```

- **不设计百分比属性**。理由是避免属性指数膨胀：百分比乘区叠在属性基数上会互相放大。
- 多个来源给同一属性的点数**直接相加**，不互相乘。
- 伤害 / 治疗的「技能数值」这一项等技能重做后才有实际消费方，公式先定。

### 减伤是唯一的例外：用百分比、且乘算

```
实际扣血 = 原始伤害 × (1 − 意志减伤) × (1 − 状态减伤)
```

意志减伤与状态减伤是**两个独立乘区，彼此相乘**，不是相加。
加法会把多个独立乘区堆到 100% 免伤；乘算永远留余量，同时带来收益递减。
减伤比例夹在 0~1，避免点数过量时出现负伤害（回血）。

## 5. 决策依据（别重复讨论）

| 结论 | 为什么 |
|:--|:--|
| 生命 / 法力不进属性列表 | 它们是当前资源，上限才是属性派生值 |
| 只做绝对值，不做百分比属性 | 避免属性与百分比乘区互相放大，指数膨胀 |
| 减伤反而用百分比且乘算 | 多个独立乘区相加会堆出 100% 免伤 |
| 智慧同时管法术伤害和法力上限 | 用户 2026-11-28 明确；否则法力上限无人负责 |
| 信仰不加成红药 | 红药是固定恢复的消耗品；信仰只加成治疗技能 |
| 属性来源只有装备 + 星图 | 不做升级分配属性点，等级仍给星点 |
| 数值全部进表 | 人工改 Excel → 导出生成物 → 代码只读生成物，代码里不许抄一份数字 |
