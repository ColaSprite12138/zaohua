## 0. 一页速览

**是什么**：2.5D 俯视角、体素画风的搜打撤（Extraction Looter）游戏，战斗手感对标暗黑破坏神 / Grim Dawn，风险规则对标逃离塔科夫 / 逃离鸭科夫。

**三个卖点**：

1. **给"鼠鼠玩家"一条活路** —— 纯 PVE 副本可以安全刷装备，不必被强制 PVP。代价是产出有硬上限。
2. **装备是消耗品，不是奖杯** —— 刻意不把顶级装备做成终极追求（Dungeonborne 的教训）。
3. **靠机制分胜负，不靠数值碾压** —— 无暴击、无部位判定，胜负来自技能释放、连招、躲避、招架、地形。

**一句话循环**：

> 带装备下场 → 打怪 / 抢事件 / 破坏物 → 攒货 → 从传送门撤离 → 局外换成更高的下一局筹码。

## 1. 定位与差异

| 项 | 我们的选择 | 参照物 |
|:--|:--|:--|
| 视角 | 2.5D 俯视角 | 暗黑 / Grim Dawn |
| 画风 | 体素（Voxel），一格一方块 | 见 `docs/art-style.md` |
| 战斗节奏 | 技能驱动，普攻为辅助 | 偏 MOBA / 动作，不偏刷怪 |
| 风险结构 | 全掉落（保险格除外） | 塔科夫 |
| 成长结构 | 星图横向铺开 | Grim Dawn 星座 |
| 玩家关系 | 可 3 人组队，也可独狼 | — |

**和市面产品的差异点**：

- 市面搜打撤基本强制 PVP，我们**给纯 PVE 玩家一条完整路径**（主线 + 副本 + 领地）
- 市面搜打撤靠"搜容器"制造静态风险，我们**用可破坏物 + 站桩窗口**替代（见 10.5）

## 2. 模式结构

```
游戏
├─ 主线关卡（Story）      —— 有剧情，可重复体验，无道具产出，失败不掉装备
│    └─ 通关 → 占领领地 → 持续产出（时间 + 材料）
├─ PVE 副本（Dungeon）    —— 无剧情，纯 PVE，产道具，品质有硬上限
└─ PVPVE                 —— 带装备进场，高价值产出，玩家互相抢，无二次机会
```

**要点**：

- **没有纯 PVP 模式**。一切 PVP 都发生在有怪的地图里，PVE 元素是强制项（逼玩家交战、暴露信息）
- PVE 副本与 PVPVE **共用同一套地图** → 玩家在 PVE 里熟悉地图，等于在 PVPVE 里获得信息优势
- 主线关卡**一次性的道具奖励**只在首通发放，关卡内不产道具；但主线给**星图点**（见 6.3）与**永久解锁**（领地 / 副本 / NPC）

### 2.1 当前阶段范围（v4 明确）

> **第 1 版先不做组队。单人 only。**

| 做 | 不做（推迟） |
|:--|:--|
| 1 名玩家 + 怪物 + 可破坏物 + 传送门 | 组队、联机同步、队友互助/救人 |
| 单人的撤离与结算 | 群体传送门、多人匹配、舔包规则 |
| 所有战斗与养成 | 团队增益、光环类星图效果 |

**为什么写死这一条**：避免照本文档开发时**过度设计** —— 提前为组队做同步层、队友状态、多人门，会让单人版本变慢且复杂。
**保留的余地**：传送门已有"开启次数"机制，天然能扩展成群体门；星图节点设计不排斥将来加团队效果。**只留余地，不提前实现。**

## 3. 核心循环

### 3.1 局外循环（长线）

```
推主线 → 占领领地 → 领地持续产出（材料 + 装备）
   ↑                        ↓
星图点数 ←──────────── 副本刷材料 / 装备
   ↓                        ↓
强化流派 ────────────→ 带更强配置下更高难度的图
```

### 3.2 局内循环（15 分钟）

见第 10 章。

### 3.3 三层经济

```
PVE 副本（出"量"，安全）
      ↓ 低阶材料
领地生产（消化材料 + 时间，出"中阶"）
      ↓
PVPVE（出"质"、独有收藏品、最高品质）
```

**设计意图**：PVE 的产出不是"次等品"，而是**领地的原料**。这样"鼠鼠玩家"的时间有去处，经济闭环不缺环。

## 4. 风险与死亡规则

| 场景 | 死亡 / 失败后果 |
|:--|:--|
| 主线关卡 | **身上 + 背包全不掉**（剧情优先，不惩罚） |
| PVE 副本 | 掉落在**死亡地点**。下一次进本可**捡回一次**；**第二次死亡 = 永久消失**（魂系捡魂 / 鸭科夫） |
| PVPVE | **无二次机会**，全部掉落，任何人可拾取 |

**细则**：

- 掉落范围：**已穿戴 10 个装备槽 + 背包全部**，**保险格除外**
- **保险格是独立容器**（对标三角洲的保险箱，2026-11-15 用户拍板）：它有自己的格子，**不占背包格**
- **保险格**是付费消耗品（格子要买），用来降低风险
- **初始赠送 2 格保险格** —— 防止新手"一直死、什么都带不出来"的死亡螺旋。扩容要花钱
- **裸装取回**是允许的，但路上有怪 —— 这是设计内的风险，不是漏洞
- **白色起步装**：进副本时若身上无装备，默认穿戴一套白装。规则：**不可带出、不可被他人拾取、不参与套装效果**（避免白装污染战利品池、避免白装凑套）

## 5. 经济系统

### 5.1 产出去向

| 物品类型 | 用途 |
|:--|:--|
| 武器 / 护甲 / 首饰 | 穿戴、被消耗（掉落 / 耐久） |
| **收藏品** | 纯换金道具，不占装备槽、占背包格、可堆叠。**极其稀有的收藏品是搜打撤的核心贪婪驱动之一**（见 7.5） |
| 低阶材料 | 领地生产原料 |
| 星图点（不可交易） | 成长，见 6.3 |

### 5.2 抗通胀：四条出口

因为我们**不做赛季重置**，通胀必须靠持续消耗压住：

| 出口 | 说明 |
|:--|:--|
| **耐久** | 近战武器按**造成 / 承受伤害**扣耐久；修理成本**随次数递增**，且**按补回量永久压低耐久上限**（修不如重铸：磨到很低就只能销毁 / 卖掉 / 换一把） |
| **消耗品** | 红药 / 蓝药 / 箭矢，全部是局内消耗 |
| **保险格** | 占格付费 |
| ~~洗点~~ | v1 曾是出口，**v2 改为免费**（见 6.4）→ 由下面一项替代 |
| **词条重铸** | 把"强化某技能"的词条重铸成别的技能；**废装变原料**，同时把"废装率"转成经济出口。落地口径：**整件重掷、每件 1 次、扣费直接生效**（数值词条这一层先做；技能附加词条是同一个 `affixes` 容器的下一层） |

### 5.3 装备消耗品化（核心原则）

> **不把"刷出顶级装备"做成玩家的终极目标。**

Dungeonborne 的教训：装备太稀有 → 玩家拿到就退游，且不敢带进战斗。所以我们：

- **不靠掉率控制稀有度**，靠**产出速率**调节供需
- 顶级装备应该"贵但常见"，是**可替换的筹码**，不是奖杯
- 套装门槛要低（见 7.3），否则凑不齐 = 不敢穿

## 6. 角色养成

### 6.1 养成四轴

| 轴 | 来源 | 给什么 | 会掉吗 | 洗点 |
|:--|:--|:--|:--|:--|
| 等级 | 击杀经验 | **星图点**（**不给基础属性**） | 不掉 | — |
| 技能 | 星图节点 | 无独立等级：**解锁即完整**，不做技能升级 / 形态变体 | 不掉 | 随星图 |
| **星图** | **等级 + 主线首通 + 主线探索事件** | 百分比乘区 + 解锁主动技能 + 被动 | 不掉 | **免费** |
| 装备 | 掉落 | 固定白值 + 词条 + 套装 + 附加效果 | **全掉** | 不可洗（只能重铸） |

> **没有"技能点"这种资源。** 全局只有一种成长货币：**星图点**。
> 技能不靠点满成长，它的强度来自星图乘区 + 装备白值。

### 6.2 分工红线

- **星图管横向**（玩法、机制、乘区）—— **主要强度来源**
- **装备管纵向**（白值 + 附加效果）—— **次要**
- **主动技能只来自星图**，装备**不增加**主动技能数量
- 被动技能来自星图 + 装备词条（"每 X 秒触发"或常驻）
- **装备不改变技能的核心定位**，只加"附加效果"（分裂、附加 DOT、免减速这类**锦上添花**），**不允许"拥有即质变"**

### 6.3 星图（对标 Grim Dawn 星座，v7 重做）

> **v7 推翻 v6 的读法**：~~路径约束 = 节点前置连线~~。用户 2026-11-15 指出：星图的核心是
> **亲和点数**，不是连线；被动也不该是"为某个主动技能加成"。已按此重做（见 15.0）。

**核心机制：亲和（affinity）**

| 项 | 规则 |
|:--|:--|
| 亲和是什么 | **只累积、不消耗**的颜色点数。六种颜色＝六种元素（火 / 冰 / 水 / 毒 / 雷 / 风） |
| 从哪来 | **每个节点都产出亲和**：技能节点给本色 2 点 + 邻色 1 点；被动节点给本色 1 点 + 邻色 1 点 |
| 有什么用 | **星座的开锁门槛**。星座只认自己颜色的亲和，例如「怒雷」需要 3 点雷亲和 |
| 没有的东西 | ❌ 节点之间的前置 / 连线 ❌ 亲和消费 ❌ 5 色之上的额外规则 |

**为什么这样更耐玩**：想开高阶星座，就得先去别的星座攒颜色 —— 而攒颜色的那些点，往往不是
你真正想要的。**取舍来自"绕路"，不是来自"点不亮"**。这是 Grim Dawn 星座真正的深度来源。

**节点分三类**（被动一律通用，**不为某个技能服务**）：

| 类型 | 给什么 | 例子 |
|:--|:--|:--|
| 主动技能 | 解锁一个技能（不带等级，解锁即完整） | 火墙 / 冰锥 / 冲锋 |
| 属性 | 通用乘区：伤害 % / 生命 % / 法力 % / 近战距离 | 「燎原」所有伤害 +5% |
| 大点（passive） | 同类乘区的更大号，单个 2 点 | 「破军」所有伤害 +12% |

> **红线**：属性与大点**不得**写成"提升某个技能"（例如"横扫伤害 +20%"）。技能的强度只来自
> 通用乘区 + 装备白值（6.2）；一旦绑定具体技能，星图就会退化成"点满自己那个技能的技能树"。

**点数来源（三条，缺一不可）**：

| 来源 | 性质 |
|:--|:--|
| **等级提升** | 稳定、可预期的日常成长 |
| **主线首通** | 一次性、结构性 |
| **主线关卡内的探索事件**（修复神龛类、特殊任务、隐藏区域） | 一次性、鼓励探索 |

> **结构性约束（重要）**：等级有上限，所以**不推完主线就拿不满全部星图点**。
> 主线不是"加速器"，是"进度门槛"——玩家总归要把主线体验完，才能解锁完整星图。

**衍生推论（自然成立，不需额外设计）**：

```
主线进度 = 星图点数上限 = 战力天花板 = 匹配分层依据
```

（接住"低难度 PVPVE 地图限制星图点数"这条设计，本质是同一条链的末端。）

**数值**：点数总量**不固定**，按实测调整。v1 写的"30 点"只是示例，不作为约束。

#### 6.3.1 点数配比（v7 暂定，开发期可调）

| 用途 | 例（当前落地的 8 星座 / 24 节点） | 说明 |
|:--|:--|:--|
| **主动技能** | 7 个 × 1 点 | 解锁便宜；技能同时还产亲和，是"顺手推色"的主要手段 |
| **属性 / 乘区** | 12 个 × 1 点 | 通用乘区，1 点/个 |
| **大点** | 4 个 × 2 点 | 高门槛星座里的甜点 |
| **起点星座** | 2 个（火 / 冰）不需亲和 | 保证第一点永远点得下去 |

**当前规模**：满级 18 点 + 主线首通 2 点 + 探索事件若干 = 约 20 点，而点满全部节点需要 **26 点**
—— 拿不全，必须取舍。

**为什么技能也产亲和**：Grim Dawn 里"顺手点的星座"同时给属性和亲和，所以过渡不亏。
如果技能只解锁技能、不产色，玩家会被迫为了开星座去点纯属性点，那是"点数被地形吃掉"的挫败。

### 6.4 流派 ≠ 角色

> **职业是 Build，不是角色。** 没有"创建角色时选法师"这回事。

- 一个角色，**星图怎么点就是什么流派**
- 换流派 = 重置星图，**完全免费、无消耗、无冷却**

**为什么免费**：

- 让玩家多体验几套 build 是好事，卡洗点会劝退
- "点一套更适合 PVE 的星图去刷副本"**没有任何问题** —— 这正是玩法自由

**洗点的位置限制（v4）**：

> **洗点只能在战局外（大厅 / 局外界面）进行，局内不能操作星图。**

- 局内**不能换 build**：带进去的是什么，这一局就是什么，打完才能改
- 所以"打 boss 前洗单体、清怪洗 AOE"只能发生在**进图之前**，不是本局中途

**代价（已知并接受）**：

- **build 没有身份感**：玩家不会觉得"我是火法玩家"，只会觉得"我在用火法"
- 取舍不来自系统，来自**仓库里有什么装备** + **这一局带哪套预设方案**
- 真正的取舍时刻被推到"赛前"，而不是"战中" —— 这也正好和搜打撤的"配装下局"节奏一致

## 7. 装备系统

### 7.1 词条分档

| 层 | 谁有 | 内容 |
|:--|:--|:--|
| **主 / 副词条** | 所有品质 | 纯数值，区间随机 |
| **套装词条** | 有套装的中高品质 | 锁血这类**强效**，**凑齐套装才生效** |
| **独立词条 = 技能附加词条** | **仅最高品质** | 分裂、附加 DOT、免减速等，**锁部位**（见 7.2） |

> 用户原话："技能附加词条和独立词条就是一回事。"不做质变，本质锦上添花。

### 7.2 附加词条锁部位（防止叠加）

**规则**：某个技能的全部附加效果，**只可能出现在同一个固定部位**上。

| 例子 | 锁定部位 |
|:--|:--|
| 火球的分裂 / 附加点燃 | **武器** |
| 位移技能的附加效果 | **鞋子** |

**为什么这样能防叠加**：同一部位只能穿一件 → 同类效果天然不会叠加，**不需要额外规则**。

**配套细则**：

- **双武器槽：只有激活槽的武器词条生效**（否则两把武器都带"强化火球"就破了约束）
- 一个技能的附加效果全锁一处 → **这个技能的成长天花板就是一件装备**（已接受：它是锦上添花，不承担成长）
- **废装率高是设计意图**：火法玩家爆到"强化冰箭"的武器，反而会被引导去试一套冰系 build（掉落引导 build 发现）。缓解手段是"词条重铸"（见 5.2）
- **词条重铸有单件上限**（每件 1–3 次）：既让废装能救活，又不让"无限重铸"变成万能解。
  **落地取最小值 = 每件 1 次**（用户 2026-11-17 决策），并且**扣费直接生效、不做新旧二选一**
  —— 见 5.2 与 15.0：重铸是一次真实的风险支出，不是预览。表里仍保留 `max_times` 列，
  将来要按品质放宽（1/2/3）只改表。

### 7.3 套装：2–4 件区间（v5 放宽）

| 件数 | 说明 |
|:--|:--|
| **2 件** | 小成套，容易凑，提供"够用"的强度 |
| **3 件** | 中成套，提供质变效果 |
| **4 件** | 大成套，只有**特定套装**才用满 4 件 |

**原则**：件数落在 **2–4 之间都合理**，不锁死统一数字 —— 不同套装可以有不同阶梯（2/4、2/3 都行）。
**不做 6 件套**：装备是消耗品 + 会掉，门槛太高 = 没人敢穿。

**已定**：只有高品质装备才有套装效果；白装不参与套装；**锁血这类强效只能做套装词条**（必须凑齐才生效）。

### 7.4 武器类型与消耗（抗通胀核心）

| 武器类型 | 普攻代价 | 耐久 | 说明 |
|:--|:--|:--|:--|
| 近战 | 免费（不耗蓝） | **消耗耐久（承受伤害为主）** | 贴身挨打多 → 掉得快 |
| 法术（法杖） | **消耗法力** | **消耗耐久（造成伤害为主，速率低）** | v3 起加耐久（v2 曾定为"不设耐久"） |
| 远程（弓/弩） | **消耗箭矢** | **消耗耐久（造成伤害为主，速率低）** | 同上 |

> **耐久损耗权重建议 承受 : 造成 ≈ 7 : 3。**
> 这样近战（贴身承受多）天然更费，远程（拉开承受少）天然更省 ——
> 给远程加耐久不会变成"额外惩罚"，只是堵住"远程完全免费"的口子。
>
> ⚠ **成本平衡不了强度。** 远程真正的强度平衡点在"**被贴脸就废**"（无法普攻 / 施法被打断 /
> 受额外伤害），不在"修装备贵"。钱只能决定谁玩得起，决定不了谁更强 —— 耐久是经济出口，不是平衡工具。

### 7.5 装备权重定位（v4 修正）

> **装备提高胜率，但不封死技术翻盘。**

**为什么装备应该提高胜率**：

- 更好的装备 = 更稀有 = 更贵 = **死亡代价更大**
- 一个赌上昂贵家当下场的人，和裸装玩家的风险完全不对等
- 所以**装备好的人胜率更高是正确的**。不能让"押注家当的人"和"零成本上场的人"胜率相当 ——
  那等于惩罚投资，装备体系直接失去意义

**唯一不能越过的边界**：

> **不能出现"操作再好也打不过"的必败局。**

装备差的一方必须存在**可执行的翻盘路径**（不是"理论上能赢"）：

| 翻盘通道 | 说明 |
|:--|:--|
| 先手 | 偷袭、埋伏、抓对方技能空窗（装备不能防偷袭） |
| 地形 | 推下高台 / 逼进毒池 —— **装备不免疫地形** |
| 控制链 | 硬控 + 反应链创造的爆发窗口 |
| 招架 | 用招架吃掉对方的核心技能 |
| 消耗 | 打光对方的药 / 法力 / 弹药，拖到资源见底 |
| 撤离 | 不强求击杀，抢门走人 —— **这也算赢** |

**数值自检（做平衡时的判断标准）**：

| 装备差距 | 期望胜率 | 判断 |
|:--|:--|:--|
| 1 档 | 4 : 6 | 正常，鼓励投资装备 |
| 2 档 | 3 : 7 | 危险区，必须保证翻盘通道足够强 |
| 3 档以上 | 1 : 9 | **不可接受**，玩家会认为"这游戏滚雪球/氪金" |

**顺带的好处**：装备既提高胜率、也提高收益（刷得快、撤得多），并与耐久咬合 ——
**好装备打得快、也用得快** → 高收益伴随高成本，净收益取决于你打得好不好。

**"贪"的驱动由谁承担**：

- 装备只提供"效率"，提供不了"我捡到宝了"的兴奋 → 这份情绪交给**极其稀有的收藏品**（见 5.1）
- 收藏品不参与战斗，纯粹是价值符号，因此可以做得极稀有而不破坏平衡

### 7.6 预设构筑（v3 替代 v2 的"耐久分档"）

**问题**：装备是消耗品 + 有耐久，那"围绕一件神装建 build"就不成立（没法花两周）。

- **v2 的设想**：给稀有装备更高耐久 → 让装备活得久一点。
- **v3 的解法（用户提出）**：既然洗点免费，索性提供**预设加点方案**（预制构筑槽）——
  捡到冰系神装，一键切到冰系构筑即可，**重建一套 build 的成本接近 0**。

**这个解法更优**：

- 不需要给装备分耐久档（少一个需要平衡的数值轴）
- 玩家可以**并行维护多套构筑**（冰法 / 火法 / 近战），捡到什么玩什么
- 把"装备引导 build 发现"从"赌运气"变成**可执行**的玩法

**结构性后果（重要）**：

> **build 的约束从"点数"整体转移到了"仓库里有什么装备"。**

你没有冰系装备，就组不出冰系 build。于是：

- **装备的多样性与产出速率，比点数预算更决定玩法丰富度**
- 仓库容量、装备保留策略（哪些留着养 build）成为玩家要真正管理的资源
- 点数的角色从"限制"变成"表达"—— 它只决定这个 build 怎么长，不决定你能不能玩

**风险**：切换零成本 → 玩家会收敛到"当前最强 build"。
天然的反制是**装备库存**（你不一定凑得出那套）+ **附加词条锁部位**（不同 build 抢不同部位）。见 R12。

## 8. 战斗系统

### 8.1 基本规则

| 规则 | 决定 |
|:--|:--|
| 暴击 | **不做** |
| 破防 / 处决 | **不做** |
| 部位判定 | **不做**（只做命中判定，2.5D 不做 FPS 的精细命中） |
| 主要输出来源 | **技能**（普攻为资源 / 收尾 / 过渡） |
| 胜负来源 | 技能释放、连招、躲避、招架、地形、套装特效 |
| 基础攻速 | 偏低（降低普攻在战斗中的比重） |
| 普攻后摇 | **可被技能 / 闪避取消**（取消本身就是技巧点） |

### 8.2 技能栏

| 项 | 规则 |
|:--|:--|
| 主动技能栏 | **7 格** |
| 位移技能 | **算主动技能，占 1 格** |
| 空格闪避 | **角色自带，独立于技能栏**（不占格） |
| 实际能带几个 | 点数预算天然把主动技能压到 **4–5 个**（因为被动也吃点数），7 格是宽松上限 |
| 技能解锁成本 | **便宜**（推荐 1 点）—— 否则玩家不敢解锁"用不上"的技能，技能库永远只有 4 个，丰富感消失 |

> **取舍发生在星图，不发生在战前**：解锁什么就带什么，没有"进图前选 4 个"的环节。
> 好处：规则简单；代价：点错技能只能洗点（免费，所以代价很低）。

### 8.3 资源与消耗品

| 资源 | 规则 |
|:--|:--|
| 生命 | 常规 |
| 法力 | **不自动恢复**。技能释放消耗（所有流派都耗，依赖度不同）。恢复靠**蓝药**（缓慢回复） |
| 弹药 / 耐久 | 见 7.4 |

> **没有"流派专属资源"**（曾经设计过战士怒气，已废弃）。
> 原因：星图是所有人共用的，专属资源放前面则人人都有，放后面则前期没有，都不成立。

### 8.4 状态效果表

**硬控**（禁止操作类）

| 状态 | 效果 | 反制 |
|:--|:--|:--|
| 晕眩 | 禁止操作 | 无解，但时长短（≤1.5s） |
| 石化 | 禁止操作 | 连点闪避缩短时长；被击碎时受额外伤害 |
| 睡眠 | 禁止操作 | 受击即醒；睡眠中首次受伤 +50% |
| 禁锢 | 禁止移动 / 位移技能 / 闪避 | **可以原地攻击、放非位移技能**（不额外给反制） |

**软控 / 削弱**

| 状态 | 效果 |
|:--|:--|
| 减速 | 移动速度降低（追逃的基础） |
| 迟滞 | 攻速 / 施法速度降低 |
| 沉默 | 禁止释放技能 |
| **缴械** | 禁止普通攻击（对法系/刺客影响天然较小，符合设计意图） |
| 目盲 | 大幅降低视野 |
| 标记 | 位置在对方小地图显示一段时间 |
| 足迹 | 留下可追踪痕迹 |
| 重伤 | 治疗效果降低（比"点燃=完全禁疗"温和的一档） |
| 破甲 | 护甲降低 |
| 易伤 | 受到伤害增加 |
| 燃蓝 | 按损失法力造成伤害 |
| CD 延长 | 技能冷却变长 |

**持续伤害**

| 状态 | 效果 |
|:--|:--|
| 流血 | 持续伤害 |
| 中毒 | 可叠层，持续伤害 |
| 点燃 | 持续伤害，**效果结束前治疗无效** |

**位移类**

| 状态 | 效果 |
|:--|:--|
| 击退 / 击飞 | 位移；撞墙 = 额外伤害 + 短暂眩晕 |
| 拉拽 | 把目标拉向自己 |
| 打断 | 打断引导类技能 |

**规则**：

- **不做状态累积条**，命中即上状态（PvP 里展示进度条太乱）
- **不做状态递减（DR）** —— 玩家已决定，理由：硬控本身是"难命中 + 长 CD + 非指向性"，且递减有理解成本。**风险见第 14 章 R1**
- **硬控均为非指向性技能，CD 较长**；越难命中，命中奖励越大
- **引导类技能必须有极显眼的引导动作**（读条提示），让对手能反应、能打断

### 8.5 反应链

只做 3 类、固定条目，**不做"状态两两组合"**（避免 N² 学习成本）。

**元素：水 / 火 / 毒 / 雷 / 冰 / 风（共 6 种）**

| 组合 | 效果 |
|:--|:--|
| 水 + 冰 | 冻结（硬控） |
| 水 + 雷 | 麻痹，向附近敌人**传导** |
| 火 + 毒 | **引爆**毒层，瞬间伤害 |
| 风 + 火 | 火势蔓延（火焰区域扩大） |
| 风 + 毒 | 毒雾扩散（中毒区域扩大） |

> 6 种元素、5 条反应，学习成本可接受。**只认这张表**，不做"任意两两组合"。
> （v5 删掉了"油"：地面可燃物属于**场景属性**，不是玩家可施加的元素。）

**物理反应**

| 组合 | 效果 |
|:--|:--|
| 击退 / 拉拽 + 墙 | 撞墙：伤害 + 短暂眩晕 |
| 击退 + 陷阱 / 毒池 / 边缘 | 地形杀 |
| 流血 + 位移 | 地面血痕，可被追踪 |
| 石化 + 击碎 | 碎裂：高额伤害，终结石化 |

**技能链**

| 组合 | 效果 |
|:--|:--|
| 控制命中 → 高伤害技能 | 必中 / 极高命中 |
| 位移技能 → 已铺好的地面效果 | 把目标送进火海 / 毒池 |

> **连招原则：每一环都必须单独有收益。** 不允许"B 技能只为 A 技能服务"——B 空了 A 也空了时，B 本身要有位置/资源/减速等价值，否则玩家不敢用。

### 8.6 招架（Parry）

**不做帧级弹反，做"招架式"**（Fiora W 类），因为俯视角 + 多目标 + 输入延迟不适合帧级判定。

| 项 | 规则 |
|:--|:--|
| 架势 | 按下进入 **0.4–0.6 秒**招架架势 |
| 生效 | 姿态内受到**正面**攻击 → 完全免伤 + 反击 |
| 方向 | **只挡正面**，侧面与背后照常受伤 |
| 失败 | **不可取消的僵直**（惩罚足够重，配得上收益） |
| 表现 | **强 hitstop + 白闪 + 金属音效**（手感 80% 来自这三样） |

### 8.7 地形（2.5D 独有优势）

| 用法 | 说明 |
|:--|:--|
| 高度差 | 高台可打下面，下面打不到上面 |
| 可推落边缘 | 击退 → 摔伤 + 脱离 |
| 撞墙 | wall bounce（伤害 + 短暂眩晕） |
| 可破坏墙 | 打穿创造新路线（与可破坏物共用系统） |

### 8.8 视觉语言（体素画风下状态必须"看得见"）

| 状态 | 表现 |
|:--|:--|
| 流血 | 地面血渍 + 红色粒子 |
| 中毒 | 绿色气泡 |
| 点燃 | 橙色火焰 + 黑烟 |
| 石化 | 灰化 + 动画停止 |
| 睡眠 | 头顶 Z |
| 眩晕 | 头顶转圈星 |
| 减速 | 脚下蓝色拖尾 |
| 招架成功 | 白闪 + hitstop + 金属火花 |
| **自己身上的状态** | **技能栏正上方一行正方形图标**（2026-11-18）：一个汉字 + 顺时针「时针阴影」+ 层数角标。阴影画的是**已经过去的比例**（扫满 = 到点），不是剩余 —— 反着写会让玩家以为还剩一大截。悬停时该格**不出阴影**（看清字形），图标上方出面板：名字（含层数）/ `剩 x.x 秒` / `分类 · 一句话` |

> 与 `docs/art-style.md` 一起维护；debuff 在画面上"看不见"就等于不存在。
>
> **怪物头顶 + 玩家脚下 + 玩家 HUD** 是同一套状态的三层读法：怪身上的用粒子/光环（8.8 上一张表），

## 10. 单局结构（15 分钟）

### 10.1 时间预算

| 项 | 时长 |
|:--|:--|
| 单局总长 | **900 秒** |
| 战斗 | 约 500 秒 |
| 移动 / 赶路 | 约 160 秒 |
| 决策 / 搜刮 / 破坏物 | 约 100 秒 |
| 撤离追逐 | 约 140 秒 |

### 10.2 三段式节奏

| 时间 | 阶段 | 玩家在做 | 系统在推 |
|:--|:--|:--|:--|
| 0:00–4:00 | **探索** | 定路线、看地形、打第一波 | 低密度怪、出生点分散、无强制战斗 |
| 4:00–11:00 | **交战** | 抢事件、打精英、打可破坏物 | **7–8 分钟高价值事件刷新**（声音 + 光效提示） |
| 11:00–15:00 | **撤离** | 往传送门跑，可能被追 | 传送门开启、怪向传送门聚集 |

> **7–8 分钟的事件刷新是每局的情绪高点**：逼玩家做"抢或收手"的决定。

### 10.3 战斗节点

一局 900 秒只够 **4–5 个节点**（每个含接近、拉怪、清场、破坏、拾取，100–140 秒）。

> **一局只能让玩家记住 3 件事** —— 节点必须有"记忆点"，不能是均匀的怪群。

**节点 = 三个选择**：

| 维度 | 选项 |
|:--|:--|
| 入口 | 正面打（快、伤）/ 绕后（慢、安全）/ 打穿可破坏墙（花时间，造新路线） |
| 层次 | 小怪（资源）、精英（威胁）、可破坏物（收益）空间交错，玩家自选顺序 |
| 出口 | 清干净（时间成本）/ 拿完就走（留怪在背后）/ 主动拉怪到别处（战术撤退） |

### 10.4 怪物角色（组合 > 单体）

| 角色 | 作用 | 设计要点 |
|:--|:--|:--|
| 填线 | 资源与节奏 | 多、脆，2–3 刀死，负责"爽" |
| 压制（远程） | 破坏站位 | 逼玩家移动、打断打可破坏物 |
| 威胁（精英） | 必须用技能应对 | 高伤 + 明显起手，可被招架 |
| 控制 | 限制行动 | 逼玩家优先处理 |
| 支援 | 给其他怪加 buff | 优先级最高，逼玩家改击杀顺序 |
| 词条（affix） | 随机性 | 火链、冰霜、吸血、狂暴 |

> **组合决定 build 是否有效**：全填线 → AOE 通吃；混支援 + 远程 → 必须点单点爆发。配装才有意义。

> **落地进度（2026-11-18）**：六类里已经有 **3 类**——填线（骷髅剑士）、压制（骷髅弓手）、
> 控制（骷髅法师：沉默 / 石化 / 火球封路），外加剑士的碎骨击（缴械）。精英 / 支援 / 词条怪
> 还没有，`monster_skill.xlsx` 的 `kind` 也已经留好了位置（新的出手形态 = 加一个 `kind`）。

### 10.5 可破坏物（替代"搜容器"）

市面搜打撤的"搜"靠 UI 遮挡制造脆弱时刻（蹲下、视野被挡、不能动），我们**用动作语言替代**：

| 设计 | 说明 |
|:--|:--|
| 高价值可破坏物需要**持续攻击 2–4 秒** | 期间**站桩、不能移动、动作锁死、有挥砍音效** |
| 更高级的需要**特殊动画（更长时间）** | 窗口更长、更响、更值得埋伏 |
| **破坏会惊醒周围的怪** | 玩家必须**先清场再破坏** —— 把静态风险变成动态风险 |
| **最高价值物需要"机关"** | 先点燃 / 击碎护罩 / 打掉守卫，窗口最长 |

> 三个要素（背身、站桩、声音）全齐，偷袭玩法成立，且比"蹲着看进度条"更符合 2.5D 的动作感。

### 10.6 撤离：传送门

**不使用"撤离点"，包装成传送门。** 必须有"撤"的过程。

**状态机**

```
关闭 ──(拉闸 / 时间事件)──→ 已激活 ──(玩家引导 8–12s)──→ 开启 ──(1 人撤离)──→ 已激活
                               ↑                                              │
                               └──────────── 次数耗尽 ──→ 关闭 ←──────────────┘
```

**规则**

| 项 | 规则 |
|:--|:--|
| 开启方式 | 玩家**引导 8–12 秒**（可视为引导技能），分 3 段进度（每段有音效/光效）。**实现取 8 秒下限**：站桩越久越像罚站，撤应该利索 |
| 打断 | **打断只清空进度，不加硬直**（v4 去掉了原 3 秒硬直：清空进度本身已经是足够的惩罚） |
| 撤离 | 开启后撤离是**瞬间**的 |
| 开启次数 | 每扇门有固定次数（例：3 次），**每次只允许 1 人撤离**，用完后进入关闭 |
| 关闭后 | 永久关闭（次数耗尽） |
| 数量关系 | **门数量 > 同时在场玩家数**（例：5 扇门 / 3 人），制造抢门压力但不制造"必死"。**具体数字与同场人数对齐**：人数变，门数与开启次数跟着变 |
| 广播事件 | 可做"拉闸"：拉闸后 1 分钟，某处传送门开启 + **全图广播**（把开门变成公开事件，制造埋伏窗口） |

**为什么不需要"开门者优先通行权"**：开门者天然离门最近，且撤离是瞬间的 —— 他不会被自己开的门坑到（除非被控住，那是玩法，不是漏洞）。

> **组队时**：一人开门、三人走的问题后议（可能做群体传送门）。当前只做单人。

## 12. 数值与经济公式

### 12.1 产出必须 ≥ 损耗 × 1.2

```
单局期望损耗 = 死亡率 × 带入装备价值
单局期望产出 = 出货价值 × 撤离率
要求：单局期望产出 ≥ 单局期望损耗 × 1.2
```

例：带入 1000、死亡率 30% → 每局损耗 300 → **每局平均要打出 360 的货**。

> 产出不够 → 玩家越玩越穷，这是**节奏问题**（局太短 / 死得太频），不是单纯数值问题。
> Dungeonborne 后期的"装备断层"通常就失衡在这里。

### 12.2 时间锚点

- 一局 900 秒 → **每小时约 4 局**
- 死亡率 30% → 每小时死 1.2 次 → 需每小时产出 1.2 套可用装备
- 所有掉落表按这个速率配（用户已授权由我配表）

### 12.3 战斗时长（TTK）锚点

| 场景 | 目标时长 | 说明 |
|:--|:--|:--|
| **PVP 常规** | **10–20 秒** | 多轮技能交换，不是"谁先手谁赢" |
| PVP 极限（刺客打法师） | **5 秒起** | 可以快，但**必须给弱势方还手空间** |
| PVE 填线怪 | 2–3 刀 | — |
| PVE 精英 | 10–20 秒 | 和玩家单挑相当 |
| **PVE boss** | **≥ 60 秒** | — |

**刻意不做短 TTK**：行业里搜打撤遭遇战通常 2–4 秒决出，我们选 10–20 秒，因为要"还手空间"和"技能交换"。

**连带后果（设计时要正面处理）**：

> TTK 长 → **先手秒不掉人** → 伏击的收益不在"一击必杀"，而在**控住 + 追击**。

所以搜打撤的"埋伏"要靠三件事撑起来，缺一个就不成立：

1. **控制**（硬控/减速）—— 让你追得上
2. **位移差**（拉拽/击退/封路）—— 让对手跑不掉
3. **信息**（标记/足迹/视野遮挡）—— 让你找得到

**PVP 伤害系数**（Q5）：数值本身灵活调，只要满足上表即可；不要为了"爽"把 PVP 拉到 2 秒。

**技能两批踩到的取舍（2026-11-15）**：

- **键位不是 1–7**：`1/2` 是武器槽、`Space` 闪避、`E` 引导门、`R` 重开，全被占住。
  技能用 `Q W T F G V C`（`shared/constants.ts::SKILL_KEYS`），HUD 格子角标读同一份常量。
- **法力真的不自动恢复**（8.3 / R6）：一局只有 100 点 + 3 瓶蓝药（缓慢回复 60 点 / 5 秒）。
  蓝药**暂时按局发瓶数**，等消耗品系统上线再改成背包物品 —— 这一条写在 CONTEXT 的「没做的部分」。
- **数值是开发期取值**（Q4「做功能时再定」）：横扫 38 / 冲锋 30 / 冰锥 26，对着夹具骷髅 66 HP 调的；
  普攻 46 仍是收尾手段（8.1）。星图乘区已经接到技能伤害上（过 `mods.damageMultiplier`）。
- **冰锥仍是直线判定**：它被定义为「瞬发走廊」（`bolt`），不是弹道 —— 弹道留给真的会飞的东西
  （箭矢 / 火球 / 骷髅箭，见 2026-11-16 那条）。两者的差别是「有没有飞行时间」，不是画得好不好看。
- **读条打断不退蓝、冷却照走**：站桩要有代价，否则 PVP 里「打断」不成立。拒绝起手则一律免费。
- **技能先默认带三个**：设计上主动技能只来自星图（6.2 / 决策 14），星图批次没开工，
  所以 `PRE_EQUIPPED_SKILLS` 先写死三个；接上星图后填这张表，`createSkillBar()` 签名不变。
- **状态与反应链一个都没做**：技能只会直接扣血，减速 / 点燃 / 冻结都要等下一个批次。

**弹道这一批踩到的取舍（2026-11-16）**：

1. **两种形态不是两个开关，是两个属性**：`targeting: 'locked'` 与 `'directional'`，都写在
   `AttackSpec` 上。指向性换「必中」，非指向性换「射程 / 溅射」—— 如果给非指向性也偷偷加追踪，
   skillshot 就不存在了，所以 `homing = 0` 是一条硬约束。
2. **弓箭的伤害与磨损时机**：箭在**命中时**才扣武器耐久（按造成的伤害），打空只丢一支箭。
   这样「远程天生省耐久」是省在命中率上，而不是白送。
3. **箭矢是物品、不是计数器**：`takeAmmo()` 从背包取一件，没箭就要**免费拒绝 + 说话**。
   为此把 `30001` 加进了三个掉落池 —— 否则弓在实战里根本没有弹药来源（这是个会静默废掉
   一整个武器类别的洞）。
4. **火球是技能不是武器**：它要蓝耗 / 冷却 / 读条，这些属于技能系统。所以 `AttackKind` 里的
   `'spell'` 仍然只是类型预留，真正的弹道法术走 `skills.ts` 的 `missile` 形态。
5. **`aimRange`（点哪炸哪）**：地面瞄准的法术要收在落点，不能一路飞到原型射程尽头 ——
   第一版就是这样，玩家点脚下反而看不到爆炸（自己也看不懂发生了什么）。

**堆叠 + 商店这一批踩到的取舍（2026-11-17）**：

1. **数量存在实例上，不存 defId**（`ItemInstance.count`）。存 defId 会让"一格 5 瓶"变成
   "所有红药都是 5 瓶"，一件被喝掉就全变 —— 和词条/耐久同一条原则：**跟着这一件走**。
2. **带实例属性的东西不叠**（词条 / 耐久 / 掷定伤害）。它们合起来以后，"这一叠里的
   第二件"从哪来就说不清，重铸一次会改掉两件。所以 `isStackable()` 直接否掉，
   而不是"叠起来但保留第一件的属性"。
3. **合堆只在入包**，拖放不合并。掉落逐件进包 ⇒ 同 defId 最多一个碎叠，不需要手动整理；
   而"拖一下数量变了"是玩家没要求的变化，不做。
4. **格数 ≠ 件数**是这一批最容易漏的坑：`countConsumable` / `ammoCount` / `treasureCount` /
   playthrough 断言全部从 `bag.length` 改成 `countOf`。漏一处就是"一箭打光一叠"或"只显示 1 瓶"。
5. **免费的补给必须删掉**。留着它，金币就没有"必须花"的出口，商店等于摆设；
   代价是新号第一局没药，所以给了 `STARTING_GOLD = 120`（开发期取值，够买 2 红 + 2 蓝）。
6. **金币 0 必须落盘**。以前省掉 0 是为了信封紧凑；商店上线后 0 是"钱花光了"的真实状态，
   省略它会让读档走"新号起始金币"兜底 —— 每次刷新白送一笔钱。
7. **保险格扩容只写在状态上**（`safeCols`），不动 `SAFE` 常量。常量是进程级的，
   改一次会把局内快照、其他存档和单测一起带跑。
8. **`play` 里按 B 打不开局内背包**：play 直接跑游戏画布，壳层没有走「出征」流程
   （`inRun=false`），`setRunBag()` 会强制关掉。堆叠的视觉证据（×N 角标）由
   `verify-meta-ui.cjs` 在真实 DOM 上断言并截图（`artifacts/verify/meta-ui-shop.png`）。

**重铸 + 修理这一批踩到的取舍（2026-11-17）**：

1. **每件只洗一次**（用户拍板，比 7.2 的 1–3 次更紧）。次数一多，"废装"就不再是问题，
   而 7.2 明确说废装率高是**设计意图**（引导换 build）。表里留 `max_times` 列，放宽只改表。
2. **不做新旧二选一**（用户拍板）。二选一让重铸变成"预览"：玩家永远只接受更好的结果，
   风险被抹掉、金币出口就失效了。代价是可能越洗越差 —— 所以只保留一个弱保护：
   掷出来**种类和原来完全一样**就重掷（最多 7 次），避免"花了钱什么都没变"。
3. **重铸不碰耐久**。5.2 把耐久与词条列成两条独立出口；重铸顺手修满等于把耐久那条吞掉。
4. **修理改成"掉上限"而不是"只涨价"**（用户拍板）：价格不变，按**实际补回的量**永久扣上限。
   比例式（0.25）而不是固定值，是为了**收敛**：上限越低 → 能补回的越少 → 掉得越少，
   武器会一路变得"修一次只回一点"，最终玩家自己选择销毁 / 卖掉 / 换一把，而不是无限续命。
   配合 `1.6^已修次数` 的涨价，早修省钱但次数贵、晚修上限掉得多，形成真实权衡。
5. **上限硬底 1 点**。`maxDurability <= 0` 的战斗语义是「不参与耐久」（演示长剑 / 消耗品），
   真磨到 0 会让一把废武器突然变成永不磨损 —— 这是比"上限很低"严重得多的 bug。
6. **品质不在实例上**。`reforge()` 第一版从 `item.quality` 读品质，而 `ItemInstance` /
   `PlacedItem` 根本没有这个字段（品质是 `ItemDef` 的展示副本），于是每次都被当成
   "未知品质"静默拒绝。现在品质**必须显式传参**，单测里有一条专门钉这个。
7. **上限读数只能有一份**。`inventory.ts::durabilityCap / durabilityCurrent` 是唯一实现，
   战斗侧 `durabilityMaxOf()` 与工坊面板都调它 —— 否则会出现"工坊说还能修 130 点、
   战斗说上限 160"这种对不上的账。
8. **工坊列表只列"现在能做点什么"的**。洗过的、修满的整行消失，而不是留一行灰按钮：
   列表本身就是状态机，行消失比按钮变灰更能说明"这件事处理完了"。

**怪物技能这一批踩到的取舍（2026-11-18）**：

1. **普攻形态也进表，不只进"技能"**。原来 `monsterSpec()` 是一个
   `if (monsterId === '200001')`，里面还硬写了 `damage: 6` / `cooldown: 1.15` / `range: 40`
   —— 而 `enemies.ts` 真正用的是表里的 `attack_damage` / `attack_interval`。也就是说
   那三个数字**改了不生效**。加技能时顺手把它拆成 `attack_kind` + `projectile` 两列，
   现在 `grep '200001' assets/combat/*.ts` 是空的。
2. **技能的状态挂在弹道上，不挂在技能上**。`projectile.xlsx::status` 是唯一来源：
   "沉默箭"就是"会沉默的弹"。技能行里再写一份必然漂移，所以 `monster_skill.xlsx` 的
   `projectile` 技能填了 `status` 会**加载即抛错**；只有 `burst`（没有弹道可挂）才允许自带。
3. **两条形态就够这一批**：`projectile`（走既有飞行体）与 `burst`（以怪为圆心的范围）。
   不强上玩家那套 7 种形态 —— 那 7 种全是"以光标为锚点"的，怪物的锚点是"玩家此刻在哪"。
4. **贵的先放**。法师三招 6 / 10 / 18 秒，按表序永远轮不到石化（火球每 6 秒抢在前面）。
   `pickMonsterSkill()` 选**冷却最长**的那一个，三招才都会出场；同 cd 时按表序，可复现。
5. **一进场就在冷却**。第一版从 0 冷却起步，结果剑士看见你就缴械，玩家一刀都砍不出来
   （既有 playthrough 直接红了）。现在每招的初始 CD = 它的 `cooldown`，起手一定先是一次普攻。
6. **白放不占 CD**。够不着、隔墙、被翻滚躲掉 —— 三种"出手了但没发生"都不写冷却，
   否则玩家会在"怪明明挥了手却没伤害"之后又等一整轮。
7. **射程必须够得着它停下的位置**。远程怪的站位是 `0.9 × 普攻弹道射程`，技能射程比它短
   就会**永远不放**（站在 504、火球 480）。表里现在 520/560/540，单测有一条专门测这个
   契约（`a projectile monster can reach the distance it stops at`）。
8. **弹道状态对玩家也要生效**。`resolveHit()` 的玩家分支此前只扣血、不挂状态 ——
   `monster_arrow` 没有 status，所以从没人发现。禁魔弹要靠这一条才成立。
9. **普攻被状态挡住要出声**。`resolveAttackOrder()` 里 `noAttack` 原本直接 `return`，
   玩家点了没反应只能怀疑鼠标坏了。现在会说「被缴械 · 这一下打不出去」。
10. **`sleep` 没做**。它和"躺在地上的怪"绑在一起（受击即醒、首次受伤 +50%），
    比这四招复杂一档，留给"会睡的怪 / 玩家的控制技"那一批。
11. **三种怪必须三种剪影**（2026-11-18 补）。第一版法师直接复用剑士的灰白骨架 + 钢剑，
    `paint.ts` 里只有一个 `monsterId === '200001' ? 弓 : 剑` 的分支 —— 于是**新怪在地图上
    看不见**：玩家找不到任何"多了一种怪"的证据，只看到 22 具长得一样的骷髅。
    现在法师有 `SKELETON_MAGE`（暗紫法袍 + 兜帽 + 紫瞳）与 `staff:gem`（细杆 + 顶端青球 +
    光晕，**单独竖直绘制**、不走挥砍旋转，否则细杆顶球会被转到斜下方读成扫帚）。
    规则写死：**凡是能在画面上对玩家做出不同行为的怪，剪影必须能分开**（与 8.8
    "看不见的 debuff 等于不存在"同一条）。单测钉住"法师模型 ≠ 剑士模型"。

**玩家状态行这一批的取舍（2026-11-18，用户要求）**：

1. **画在 canvas 里，不是 DOM 浮层**。HUD 全在 `paint.ts`，一条状态行单独用 DOM 会带来
   两套坐标系（视图 1280×720 vs 窗口像素 × DPR），2× 渲染下必然对不齐。
2. **阴影 = 已流逝，不是剩余**。用户的原话是「时针一样的阴影顺时针扫」—— 扫过去的部分
   变暗，扫满 = 到点。反着写（阴影 = 剩余）会让"快没了"看起来像"还剩一大截"。
3. **悬停的那一格不画阴影**。「时钟」和「说明」是两种读法：指针指着它时，字形要全亮
   才读得清，精确剩余时间交给上面那块面板。两种信息同时压在 34px 上，谁都读不清。
4. **几何与命中是同一份数据**（`status-bar.ts` 的 `icons` 既用于画也用于 `statusBarHit`）。
   分两套算必然出现"指着图标、提示不出来"，而这类 bug 在截图里看不出来。
5. **贴技能栏上沿、左端对齐、向右生长**。状态和技能是同一块信息（"我现在是什么状态" +
   "我现在能按什么"），不该分到屏幕两头。放不下先缩格子（34→24）再砍尾（12 个上限）。
6. **一格一个字**，不用图形图标：18 条状态做 18 个体素图标，成本和"一眼认得出"不成正比；
   汉字在 34px 上比任何符号都准。字形两两不同由单测钉住。
7. **`total` 坏掉一律当"已到点"**。宁可显示成马上要没，也不要显示成"还剩一辈子"——
   后者会让玩家在硬控里一直等一个永远不会结束的状态。
