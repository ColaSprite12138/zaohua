**技能两批踩到的取舍（2026-11-15）**：

- **键位不是 1–7**：`1/2` 是武器槽、`Space` 闪避、`E` 引导门、`R` 重开，全被占住。

**弹道这一批踩到的取舍（2026-11-16）**：

1. **两种形态不是两个开关，是两个属性**：`targeting: 'locked'` 与 `'directional'`，都写在
   `AttackSpec` 上。指向性换「必中」，非指向性换「射程 / 溅射」—— 如果给非指向性也偷偷加追踪，
   skillshot 就不存在了，所以 `homing = 0` 是一条硬约束。
2. **弓箭的伤害与磨损时机**：箭在**命中时**才扣武器耐久（按造成的伤害），打空只丢一支箭。
   这样「远程天生省耐久」是省在命中率上，而不是白送。
3. **箭矢是物品、不是计数器**：`takeAmmo()` 从背包取一件，没箭就要**免费拒绝 + 说话**。
   为此把 `30001` 加进了三个掉落池 —— 否则弓在实战里根本没有弹药来源（这是个会静默废掉
   一整个武器类别的洞）。
4. **火球是技能不是武器**：它要蓝耗 / 冷却 / 读条，这些属于技能系统。所以 `AttackKind` 里的
   `'spell'` 仍然只是类型预留，真正的弹道法术走 `skills.ts` 的 `missile` 形态。
5. **`aimRange`（点哪炸哪）**：地面瞄准的法术要收在落点，不能一路飞到原型射程尽头 ——
   第一版就是这样，玩家点脚下反而看不到爆炸（自己也看不懂发生了什么）。

**堆叠 + 商店这一批踩到的取舍（2026-11-17）**：

1. **数量存在实例上，不存 defId**（`ItemInstance.count`）。存 defId 会让"一格 5 瓶"变成
   "所有红药都是 5 瓶"，一件被喝掉就全变 —— 和词条/耐久同一条原则：**跟着这一件走**。
2. **带实例属性的东西不叠**（词条 / 耐久 / 掷定伤害）。它们合起来以后，"这一叠里的
   第二件"从哪来就说不清，重铸一次会改掉两件。所以 `isStackable()` 直接否掉，
   而不是"叠起来但保留第一件的属性"。
3. **合堆只在入包**，拖放不合并。掉落逐件进包 ⇒ 同 defId 最多一个碎叠，不需要手动整理；
   而"拖一下数量变了"是玩家没要求的变化，不做。
4. **格数 ≠ 件数**是这一批最容易漏的坑：`countConsumable` / `ammoCount` / `treasureCount` /
   playthrough 断言全部从 `bag.length` 改成 `countOf`。漏一处就是"一箭打光一叠"或"只显示 1 瓶"。
5. **免费的补给必须删掉**。留着它，金币就没有"必须花"的出口，商店等于摆设；
   代价是新号第一局没药，所以给了 `STARTING_GOLD = 120`（开发期取值，够买 2 红 + 2 蓝）。
6. **金币 0 必须落盘**。以前省掉 0 是为了信封紧凑；商店上线后 0 是"钱花光了"的真实状态，
   省略它会让读档走"新号起始金币"兜底 —— 每次刷新白送一笔钱。
7. **保险格扩容只写在状态上**（`safeCols`），不动 `SAFE` 常量。常量是进程级的，
   改一次会把局内快照、其他存档和单测一起带跑。
8. **`play` 里按 B 打不开局内背包**：play 直接跑游戏画布，壳层没有走「出征」流程
   （`inRun=false`），`setRunBag()` 会强制关掉。堆叠的视觉证据（×N 角标）由
   `verify-meta-ui.cjs` 在真实 DOM 上断言并截图（`artifacts/verify/meta-ui-shop.png`）。

**重铸 + 修理这一批踩到的取舍（2026-11-17）**：

1. **每件只洗一次**（用户拍板，比 7.2 的 1–3 次更紧）。次数一多，"废装"就不再是问题，
   而 7.2 明确说废装率高是**设计意图**（引导换 build）。表里留 `max_times` 列，放宽只改表。
2. **不做新旧二选一**（用户拍板）。二选一让重铸变成"预览"：玩家永远只接受更好的结果，
   风险被抹掉、金币出口就失效了。代价是可能越洗越差 —— 所以只保留一个弱保护：
   掷出来**种类和原来完全一样**就重掷（最多 7 次），避免"花了钱什么都没变"。
3. **重铸不碰耐久**。5.2 把耐久与词条列成两条独立出口；重铸顺手修满等于把耐久那条吞掉。
4. **修理改成"掉上限"而不是"只涨价"**（用户拍板）：价格不变，按**实际补回的量**永久扣上限。
   比例式（0.25）而不是固定值，是为了**收敛**：上限越低 → 能补回的越少 → 掉得越少，
   武器会一路变得"修一次只回一点"，最终玩家自己选择销毁 / 卖掉 / 换一把，而不是无限续命。
   配合 `1.6^已修次数` 的涨价，早修省钱但次数贵、晚修上限掉得多，形成真实权衡。
5. **上限硬底 1 点**。`maxDurability <= 0` 的战斗语义是「不参与耐久」（演示长剑 / 消耗品），
   真磨到 0 会让一把废武器突然变成永不磨损 —— 这是比"上限很低"严重得多的 bug。
6. **品质不在实例上**。`reforge()` 第一版从 `item.quality` 读品质，而 `ItemInstance` /
   `PlacedItem` 根本没有这个字段（品质是 `ItemDef` 的展示副本），于是每次都被当成
   "未知品质"静默拒绝。现在品质**必须显式传参**，单测里有一条专门钉这个。
7. **上限读数只能有一份**。`inventory.ts::durabilityCap / durabilityCurrent` 是唯一实现，
   战斗侧 `durabilityMaxOf()` 与工坊面板都调它 —— 否则会出现"工坊说还能修 130 点、
   战斗说上限 160"这种对不上的账。
8. **工坊列表只列"现在能做点什么"的**。洗过的、修满的整行消失，而不是留一行灰按钮：
   列表本身就是状态机，行消失比按钮变灰更能说明"这件事处理完了"。

**怪物技能这一批踩到的取舍（2026-11-18）**：

1. **普攻形态也进表，不只进"技能"**。原来 `monsterSpec()` 是一个
   `if (monsterId === '200001')`，里面还硬写了 `damage: 6` / `cooldown: 1.15` / `range: 40`
   —— 而 `enemies.ts` 真正用的是表里的 `attack_damage` / `attack_interval`。也就是说
   那三个数字**改了不生效**。加技能时顺手把它拆成 `attack_kind` + `projectile` 两列，
   现在 `grep '200001' assets/combat/*.ts` 是空的。
2. **技能的状态挂在弹道上，不挂在技能上**。`projectile.xlsx::status` 是唯一来源：
   "沉默箭"就是"会沉默的弹"。技能行里再写一份必然漂移，所以 `monster_skill.xlsx` 的
   `projectile` 技能填了 `status` 会**加载即抛错**；只有 `burst`（没有弹道可挂）才允许自带。
3. **两条形态就够这一批**：`projectile`（走既有飞行体）与 `burst`（以怪为圆心的范围）。
   不强上玩家那套 7 种形态 —— 那 7 种全是"以光标为锚点"的，怪物的锚点是"玩家此刻在哪"。
4. **贵的先放**。法师三招 6 / 10 / 18 秒，按表序永远轮不到石化（火球每 6 秒抢在前面）。
   `pickMonsterSkill()` 选**冷却最长**的那一个，三招才都会出场；同 cd 时按表序，可复现。
5. **一进场就在冷却**。第一版从 0 冷却起步，结果剑士看见你就缴械，玩家一刀都砍不出来
   （既有 playthrough 直接红了）。现在每招的初始 CD = 它的 `cooldown`，起手一定先是一次普攻。
6. **白放不占 CD**。够不着、隔墙、被翻滚躲掉 —— 三种"出手了但没发生"都不写冷却，
   否则玩家会在"怪明明挥了手却没伤害"之后又等一整轮。
7. **射程必须够得着它停下的位置**。远程怪的站位是 `0.9 × 普攻弹道射程`，技能射程比它短
   就会**永远不放**（站在 504、火球 480）。表里现在 520/560/540，单测有一条专门测这个
   契约（`a projectile monster can reach the distance it stops at`）。
8. **弹道状态对玩家也要生效**。`resolveHit()` 的玩家分支此前只扣血、不挂状态 ——
   `monster_arrow` 没有 status，所以从没人发现。禁魔弹要靠这一条才成立。
9. **普攻被状态挡住要出声**。`resolveAttackOrder()` 里 `noAttack` 原本直接 `return`，
   玩家点了没反应只能怀疑鼠标坏了。现在会说「被缴械 · 这一下打不出去」。
10. **`sleep` 没做**。它和"躺在地上的怪"绑在一起（受击即醒、首次受伤 +50%），
    比这四招复杂一档，留给"会睡的怪 / 玩家的控制技"那一批。
11. **三种怪必须三种剪影**（2026-11-18 补）。第一版法师直接复用剑士的灰白骨架 + 钢剑，
    `paint.ts` 里只有一个 `monsterId === '200001' ? 弓 : 剑` 的分支 —— 于是**新怪在地图上
    看不见**：玩家找不到任何"多了一种怪"的证据，只看到 22 具长得一样的骷髅。
    现在法师有 `SKELETON_MAGE`（暗紫法袍 + 兜帽 + 紫瞳）与 `staff:gem`（细杆 + 顶端青球 +
    光晕，**单独竖直绘制**、不走挥砍旋转，否则细杆顶球会被转到斜下方读成扫帚）。
    规则写死：**凡是能在画面上对玩家做出不同行为的怪，剪影必须能分开**（与 8.8
    "看不见的 debuff 等于不存在"同一条）。单测钉住"法师模型 ≠ 剑士模型"。

**玩家状态行这一批的取舍（2026-11-18，用户要求）**：

1. **画在 canvas 里，不是 DOM 浮层**。HUD 全在 `paint.ts`，一条状态行单独用 DOM 会带来
   两套坐标系（视图 1280×720 vs 窗口像素 × DPR），2× 渲染下必然对不齐。
2. **阴影 = 已流逝，不是剩余**。用户的原话是「时针一样的阴影顺时针扫」—— 扫过去的部分
   变暗，扫满 = 到点。反着写（阴影 = 剩余）会让"快没了"看起来像"还剩一大截"。
3. **悬停的那一格不画阴影**。「时钟」和「说明」是两种读法：指针指着它时，字形要全亮
   才读得清，精确剩余时间交给上面那块面板。两种信息同时压在 34px 上，谁都读不清。
