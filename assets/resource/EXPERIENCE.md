# EXPERIENCE — resource 独立经验库

> 只记本模块踩坑，按条追加、不删历史。契约见 `CONTEXT.md`。

## 2026-11-10 · 数据表边界

- 用户明确：人改的是 Excel，后面再转换成程序易读结构（如 bytes）。因此本轮只建目录与约定，
  **不实现转换器、不预造假数据**；`generated/` 目录可以不存在，测试需容忍。
- 文件名强制小写 snake_case `.xlsx`：Windows 大小写不敏感，混用大小写会在换机器/Linux 时导出失败。
- 禁止公式与合并单元格：导出器不求值，公式会变成字符串进到数值字段里，且这种错误在运行时才暴露。
- 数值唯一权威在本目录。若某模块图省事把表复制成代码常量，之后改 Excel 不会生效 ——
  新增表必须在消费方 `CONTEXT.md` 登记，便于 AI 发现「这份数据有人用」。

## 2026-11-11 · 首次接表

- 用户把表放在工程根 `xls/`（`item.xlsx` 中文表头、`loot.xlsx` 双 Sheet），与既有约定不符。
  **先确认再搬**：用选项让用户拍板「按约定搬移并规范」vs「就地适配」，避免擅自改用户的数据入口。
- 规范化时只做**结构**转换，数值一个不动：中文表头 → 英文 snake_case、首列补唯一 `id`、
  `10,15` 拆成两个数值列、多 Sheet 拆成多张单 Sheet 表。伤害范围留在字符串里会让消费方
  每次 split，且品质/权重无法被类型检查。
- 转换器刻意用 Python 标准库手写 OOXML 解析，不引 openpyxl：本机有 3.7.7 与 3.13.12 两套
  Python，装第三方包会绑定到某一套，验收脚本换解释器就崩。写完必须**回读**生成的 xlsx 验证，
  手写 zip 包最容易漏 `[Content_Types].xml` 的 Override 导致 Excel 打不开。
- 手写 OOXML 导出 xlsx 时用 `t="inlineStr"` 存中文最省事，不用维护 sharedStrings 索引。
- `--check` 防漂移沿用 `build-meta-ui.mjs` 的模式：重新在内存里渲染一遍，与磁盘逐字比对，
  并顺带检测「有生成物没源表」的孤儿；源 SHA-256 写进文件头便于人工追溯。
- 生成物是 `.ts` 常量数组（`as const`）而非 JSON：ForgeAX 打包链对 TS import 路径固定，
  不需要额外 resolve 配置，且 Row 类型可直接 `typeof` 推导，零手写 schema。
