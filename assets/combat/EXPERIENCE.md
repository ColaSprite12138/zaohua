## 2026-11-10 · 目录工程化拆分

- 原来 `assets/game/simulation.ts` 一个文件承载全部玩法（498 行）。按职责拆成 state / effects /
  movement / attack / enemies / weapons / modifiers / simulation 八个文件，**保留旧路径为纯 re-export
  门面**，因此 `paint.ts`、`game.pack.ts`、13 条单测与两个 playthrough 一行未改就全绿。
  结论：重构已有工程时，先加一层稳定门面再搬实现，是零回归的最低成本做法。
- `state.ts` 不 import 任何其他 combat 文件（只 import `shared/`），否则各子系统拿类型时会形成环。
- 天赋效果钩子放在 combat 而不是 talent：talent 只输出 `effectIds`，战斗解释执行。
  这样依赖单向，不会出现「天赋读战斗数值、战斗读天赋加成」的双向耦合。
- `swingAtTarget` / `resolveAttackOrder` 增加 `CombatModifiers` 参数但默认 `NO_MODIFIERS`，
  保证新增扩展点不改变任何既有数值与断言。

## 2026-11-10 · 双武器槽与 1/2 切换

- **扩展装备位时保留旧投影字段名**：`equippedWeapon` 被 32 步 playthrough 三处断言依赖，
  改成"当前激活槽武器"的语义即可零改动兼容；删字段或改名会连带改大量脚本。
- **单一取值入口**：`activeWeapon(s)` 统一供 `attack.ts` / `paint.ts` / `projection` /
  `checkCleared` 使用。若某处直接读 `weaponSlots[0]` 或 `some(Boolean)`，切到空槽后
  仍会打长剑伤害，而且只在"按 2 之后"才复现。
- `checkCleared` 用 `weaponSlots.some(...)`（是否拿到过武器）而**不是** `activeWeapon`：
  用后者时玩家切到空槽会导致通关提示永远不触发，属于无意义的行为回归。
- `StepInput.switchWeapon` 设为**可选**：老单测的 `input()` 构造器用 `Partial<StepInput>`
  提供默认字段，改必填会连累 11 条 movement 单测一起编译失败。
- `game.pack.ts` 把 `justPressedCode('Digit1'/'Digit2')` 映射成 `0 | 1 | null`；
  浏览器验收必须真的 `play.keyboard.press('Digit2')` 再 `advance(0.15)`，
  光靠单测调 `step()` 覆盖不到引擎键盘码映射这一层。
- vitest 的 `toBe()` 不收第二个 message 参数，带说明请改用 `node:assert/strict`。

## 历史踩坑（迁移自 docs/feedback.md，详见原文第 11–13 条）

- `justReleased` 释放沿要等引擎下一帧才结算，playthrough 点敌人后需 `play.wait(100)` 再读投影。
- 敌人会追到落点旁，四象限地面点击可能被判成点敌人 → 移动类验收步骤前按 R 重开隔离。
- Worker 里没有 `document` / `gameHost.canvas`，输入坐标必须用每帧 `host.drawingBufferSize()`
  换算；用固定 1280×720 分母会让大窗口下人物往反方向跑。`game/` 层负责这件事，combat 只吃逻辑坐标。

## 2026-11-11 · 权重掉落与多怪部署

- **掉落数值只从 `resource/generated/*.ts` 读，禁止在 combat 里硬编码**：怪物 → `monster.loot_pool_id` → `loot_pool` 权重 → `item` 属性。`rollLoot(monsterId, rng)` 是唯一抽取入口，`loot-report.mjs` 必须直接 import 它，不要另写一份镜像算法（影子逻辑会让报告全绿但战斗实际错）。
- **固定种子可复现**：`makeRng(seed)` 用 Mulberry32，`createState({ seed })` / `deployRun({ seed })` / `reset()` 都从 `runSeed` 重建 rng；R 重开后 loot 序列必须一致，这是单测之一。
- **默认仍 2 只怪**（历史记录，2026-11-13 已作废）：当时 `spawnSkeletons(count)` 前两只保留原坐标，额外怪按网格生成并交替 `100001` / `200001`；多怪只通过 `deployRun()` 或 `createState({ monsterCount })` 注入，否则 35 步 playthrough 的 `skeletonsAlive === 2` 断言会红。**现行**：`spawnFromMap(map)` 是唯一入口，运行时没有怪数字段。
- `Drop.kind` 保留 `'longsword'` 作为**视觉/兼容类别**，真实物品身份走 `drop.itemId`；`WeaponId` 也保持 `'longsword'` 表示「armed vs bare」，不要改成表里的 12 个 id，否则 11 条 movement + 7 条 weapons 单测全要重写。
- **槽满也要计入战利品**：两槽已满时拾取折算 80 分，但 `carriedItems.push(drop.itemId)` 必须先执行，否则搜打撤结算会漏掉这件战利品。
- `GameProjectionValue` 不接受 `interface`（缺索引签名）也不接受 `readonly T[]`（要求可变数组）；`RunResult` 用 `type` + 可变字段。`projection()` 加字段只能**追加**，旧字段 `equippedWeapon` 不能改名。
- 跑批报告样本量要够：`--samples 1000` 时尾部稀有项偏差可到 1.3%，会因方差本身触发 1% 阈值；验收固定 31000/池（总权重 31，每格期望 ≥1000 次）。
- **`game.state` 必须是唯一 read projection**：曾为「Play 验收驱动部署」额外注册 `run.result` / `run.deploy`，结果 `project play` 以「唯一 projection」解析默认读取，多一个就让 35 步 playthrough 首步报 `state-unavailable`（脚本里明明都写了 `play.state('game.state')`）。部署与结算走 BroadcastChannel 即可，不要为了「将来可能有用」加 projection seam。这只有全量验收能抓到。

## 2026-11-12 · 删除得分、显式拾取与跨堆背包协议

- **删 `score` 要连投影一起删**：除了 `GameState.score`，还有 `attack.ts` 的击杀 / 拾取加分、
  `projection()` 里的 `score` 字段、`paint.ts` 的右上角 HUD 与结算板、`playthrough.mjs` 的
  「score never decreases」。只删状态字段会让 `tsc` 与浏览器断言同时红。HUD 换成
  `击杀 / 剩余骷髅 / 已拾取`，结算板换成 `击杀 / 拾取`，并新增 `'score' in equipped === false` 反例断言。
- **显式拾取指令必须落在释放沿短按分支**：`movement.ts` 用 `dropAtPoint()` 判断短按是否点中掉落物，
  命中才写 `s.pickupTarget = drop.uid`，点地面 / 点敌人一律清空；长按 `follow` 分支也要清
  `pickupTarget`。`updateDrops()` 只在 `pickupTarget !== null && pendingPickup === null`
  且玩家距掉落物 `< 50px` 时结算 —— **走过掉落物绝不自动拾取**。
- **掉落物必须有稳定 uid**：跨堆 `pickup` / `pickupAck` 靠 uid 对齐具体掉落物。
  `state.ts::nextDropUid()` 用模块级单调递增计数器（跨局不重置，避免与上一局背包 uid 撞车）；
  所有手工构造 `s.drops` 的单测都要补 `uid`，否则 ack 永远匹配不上。
- **`pendingPickup` 不能整个对象进投影**：`GameProjectionValue` 不接受 `interface`（缺索引签名），
  只投影 `s.pendingPickup ? s.pendingPickup.uid : null`；直接塞对象会 `tsc` 报错。
- **每帧要防止重复发消息**：`game.pack.ts` 用 `pickupSent` 记住已发 uid，只有
  `pendingPickup !== null && pickupSent === null` 才发 `pickup`；收到 `pickupAck`、
  `deploy` 或 R 重开时清空。否则主窗口会 `addToBag()` 多次，同一件战利品塞进背包好几份。
- **背包满时掉落物留在地上**：`resolvePickupAck(s, false, uid)` 只清 pending 并提示，
  **不移除 drop、不写 `runBagUids`**；`ok=true` 才移除掉落物并记 uid。这是用户
  「身上和背包都满了就捡不起来」的落点。
- **结算字段分工**：`slotLootItemIds`（拾取进武器槽的 authored id，通关时找格子入库）与
  `runBagUids`（局内已占背包的 uid，阵亡时按 uid 从 `bag` 删除）不能混成一个 `carriedItems`；
  `carriedItems` 只用于 HUD / 报告数量。
- **旧断言改成反例而不是删**：`loot.test.ts` 原「走过去自动拾取」改成显式设 `pickupTarget` 后拾取，
  并新增「不点击时走过掉落物不会拾取」；`playthrough.mjs` 的 35 步不变，拾取步骤前新增
  「掉落物还在地上、`equippedWeapon` 为 null」，拾取后断言 `drops.length === 0`。

## 2026-11-13 · 地图运行时接线：世界坐标 / 相机 / A* / 碰撞 / 只读小地图

- **投影屏幕归一化千万不能改成世界归一化**：37 步 playthrough 与 4 步 resize 全靠
  `player / skeletons / dropAt / target` 是「屏幕坐标 / VIEW_W,/VIEW_H」。相机一跟随，
  世界坐标固定的 `target` 投影会随相机漂移。做法是 `projection()` 里 `worldToScreen()`
  再除，旧字段不动，世界事实另开 `worldPlayer / camera / map / pathLength`。
- **测试夹具必须 ≤ 视口**：最初写 40×24 格 = 1280×768，`cameraFor()` 把 y clamp 到 48，
  所有浏览器断言整体偏移。改 22 行 = 704 后 `cameraFor()` 的两个上限都是 0，相机恒 `(0,0)`，
  旧坐标 `(400,470)` / `(880,430)` / `(1010,560)` 全部原样可用，验收脚本零改动。
- **`setTarget()` 每帧被攻击追击调用**：A* 不能每帧重跑。目标格变化 <12px 时复用 `s.path`，
  `walk()` 沿格中心逐点走、到点 shift；path 空后再直追 `s.target`。
- **7 只怪每帧 A* 太贵**：每只 `repath` 0.7s 节流 + 分轴滑动 `canStand()`；否则正式地图
  怪物会卡在墙后，清场条件永远不成立。
- **`paint.ts` 只需一次 `g.translate(-cam.x,-cam.y)`** 包住地形 / 角色 / 掉落 / 粒子，
  所有既有绘制函数继续用世界坐标不用改；HUD 与小地图必须在 `restore()` 之后画。
- **「小地图只能看不能点」是输入侧的事**：只在画布上画出小地图没用，必须在
  `game.pack.ts` 把落在 `MINIMAP` 矩形内的 `pointerDown/Held/Up` 全部丢弃。
- **`deploy` 是两张地图的唯一切换点**：真正玩必经局外出征，自动验收 `project play`
  不出发，所以「默认测试夹具 / deploy 后正式 arena.ldtk」正好等价于「验收用测试图、玩用正式图」，
  不需要检测运行环境或加 URL 参数。
- **删旧竞技场要连根删**：`backdrop()` / `ground()` / `GROUND_TOP` / 一屏 clamp /
  `spawnSkeletons()` 硬编码坐标 / `/VIEW_W` 归一化一起清；本批先把 `monsterCount` 由
  「可注入」改成「只读派生自 `map.monsters.length`」，随后按用户 2026-11-13 的要求
  把该字段从状态 / 部署协议 / 投影 / 结算 / ack / 局外 UI / 日志里**全部删干净**。

## 2026-11-13（续二）— 局内武器槽事件化，供主窗口角色面板同步

- **Worker 的 `weaponSlots` 只是 `WeaponId='longsword'` 兼容类别**，真实身份在
  `slotLootItemIds` / drop 的 `itemId`。要让玩家在局内角色面板看到具体武器，必须把
  `uid / itemId / slot` 一起带过去；只发一个布尔「有武器」不够。
- **纯逻辑层不要引入 IO**：`weapons.ts::updateDrops()` 只 `push` 到
  `GameState.weaponLootEvents`；`game.pack.ts` 在 `step()` 之后、`settleIfFinished()` 之前
  drain 并 `postMessage({ type: 'weaponLoot' })`。事件不进 `projection()`，避免污染
  `GameProjectionValue` 与 37 步 playthrough 的字段快照。
- **事件队列必须随 `reset()` 清空**：`setArena()` / R 重开都会 `reset()`，否则上一局
  的装备事件会在新一局被重放，主窗口往已占用的槽写实例。
- **两槽都满的分支不变**：仍走 `pickup` / `pickupAck` 进背包；`weaponLoot` 只对应
  「装进空武器槽」这一种路径，不要混成一个协议。

## 2026-11-13（续四）— 指针反馈 / 命中容错 / 身体碰撞

- **光标属于 presentation realm**：Engine Worker 里没有 `document`、`gameHost.canvas` 是
  `undefined`、`uiRoot` 在 source-only realm 被省略，**没有任何设光标的接口**（已记入
  `docs/feedback.md`）。不要试图在 `paint.ts` 里画一个"假光标"再隐藏系统光标——软件 adapter
  只有几 fps，画出来的光标会拖影；CSS 游标是合成器驱动的，永远跟手。
- 正确做法：Worker 只在 `hoverEnemy` **变化时**广播 `{ type:'hoverEnemy', index }`，
  主窗口 `meta-ui/shell-bridge.js` 设 `#app.style.cursor`（内联 SVG data-URI，热点在剑尖）。
  逐帧发消息既浪费也没必要。
- **光标与点击必须共用同一个 `hitTestEnemy()`**：两套判定一旦漂移，就会出现「光标变剑但点不动」
  这种最招骂的组合。`hoverEnemy` 在 `step()` 末尾算，描述的正是这一帧要画出去的画面。
- 追击中的骷髅一直在动，严格贴贴图会点不中：盒外给 46px **躯干半径容错**，但**盒内命中优先**，
  多个候选取躯干最近的。点击在**释放沿**用释放点结算（不用按下点），移动目标明显更好点。
- **身体碰撞是软推开，不是硬阻挡**：`separate()` 各让一半，被墙卡住的一方把份额让给对方；
  推挤位移本身也要过 `canStand()`。硬阻挡会让怪物把玩家顶在墙上动不了。
  玩家击退怪物（`swingAtTarget` 里 +16/+12px）会制造重叠，所以分离必须排在击退之后。
- **坑：`scripts/verify-shell.cjs` 的 SELFTEST 是一个模板字符串**，里面写正则要二次转义
  （`\\(` 才输出 `\(`）。写错时整个脚本**解析失败**，页面只会一直显示 `PENDING`，
  完全没有报错——排查时先把页面里最后一个 `<script>` 抠出来 `node --check`。
  同类判断优先用 `indexOf`，别在两层字符串里写正则。

## 2026-11-13（续五）— 点击判定不能看时长

- 症状：悬停时鼠标已经是长剑光标，点下去人物却只是走过去。原因是单击判定用了
  `elapsed >= CLICK_HOLD_SECONDS(0.35s)`，**人手一次认真点击常常超过 350ms**，
  被判成「长按跟随」；光标承诺攻击、点击执行移动，两者直接矛盾。
- 定论：**单击 = 没有拖动**，与按住多久无关。`hold` 只在指针位移超过
  `CLICK_DRAG_PIXELS(12)` 时置位；`press.elapsed` 与 `CLICK_HOLD_SECONDS` 已删除。
  长按跟随仍然存在，但必须真的拖着走（这也正是跟随唯一有意义的用法）。
- 教训：**任何"时长"阈值都要按人手最慢的点击来定**，动作游戏的点击按 400–600ms 估；
  更好的办法是根本不看时长，改用「有没有发生位移」这种意图明确的信号。
- 护栏：`movement.test.ts::click duration must not change the action`（慢按不动的
  press 仍然攻击 / 地面仍是移动）、`playthrough.mjs`「a slow stationary click on an enemy
  still attacks」（真实 450ms 慢点击）。

## 2026-11-13（续六）— 镜头滚动让点击退化，是坐标系问题

- 症状：角色在走（镜头在滚）时，点怪物下发的是移动指令；点空地也偶发「像没点到」。
- 根因一：**按下点存的是世界坐标**，而「有没有拖动」用世界坐标差判断。玩家一走，镜头跟着滚，
  同一屏幕位置下的世界坐标每帧都在变（实测 205px/s ⇒ 约 0.2px/ms，250ms 漂 54px），
  纹丝不动的光标 60ms 后就「拖动」超阈值 → 单击被判成长按跟随 → 只走不打。
  **正解：位移判定永远在屏幕空间**，`view = mouse − camera` 由战斗层自己算（引擎只给世界坐标，
  别为此新增第二个输入字段——试过，引擎侧不稳）。
- 根因二：结算点曾经改成「释放帧的世界点」，镜头一动就瞄到怪物滑走之后的位置（54px 外）。
  **正解：用按下那一刻的世界点**（`press.wx/wy`），那才是玩家瞄准的目标；容差仍是 46px 躯干。
- 根因三（偶发丢点击）：输入快照只在**有指针事件的帧**带 `position`。`game.pack.ts` 现在记住
  最后一次位置并在缺位置时复用，避免「按下帧没有位置 → press 没建立 → 整次点击丢失」。
- 排查教训：用 `project play` 复现时，`mouse.up()` 之后**必须等一帧**再读状态，否则读到的是
  处理释放之前的快照——我自己被这个竞态骗了三轮，误以为修复无效。

## 2026-11-14 — 掉落物「26px 大圈优先」把怪物整只吃掉了

- 症状：怪物和掉落物重叠时，左键怎么点都只会捡东西，打不到那只怪。玩家只能先把怪引开，
  或者先走开再回来。这是拾取优先规则的副作用，不是拾取本身的问题。
- 根因：`dropAtPoint()` 用「距掉落中心 ≤26px」判定，而怪物躯干盒只有 `|dx|≤30`、
  `y∈[-70,+12]`，两只脚附近完全被这 26px 圆覆盖 → 点击在怪身上也命中了掉落。
- 定论（用户 2026-11-14 决策）：**掉落物拆成「很小的地面模型 + 可点的名字牌」**。
  - 模型缩到 12×35px（旧的是 46px 长剑 + 68×20 名牌），可点范围只有 `DROP_MODEL_RADIUS=12`。
  - 名字牌 `dropLabelRect()` 是可见的点击目标：底边 `drop.y-34`、高 20，**刚好在躯干中心
    `-30` 之上**，所以点胸口仍然是攻击、点名字才是拾取。
  - 名字牌画在**所有身体之后**（独立一层），怪物站在掉落上也挡不住名字；悬停时牌面变白框白字，
    `hoverEnemy` 置空 → 主窗口把长剑光标复位成移动指针。
  - 点中牌子时落点仍取 `drop.x/drop.y`（牌面浮空，直接把落点设到牌上会去撞墙/走空）。
- 教训：**「优先级」要绑定到玩家明确指到的物件，而不是一个以物件为圆心的猜测半径**。
  半径越大越容易误吞别的可点目标；把可点区域做成玩家看得见的东西（名字牌），
  优先级就和意图一一对应了。
- 护栏：`movement.test.ts`「hovering a drop name plate … suppresses the sword」
  「clicking the name plate loots even with a monster standing on the drop」
  「a click beside the tiny model is a plain move」；`playthrough.mjs` 拾取步骤改为
  悬停并点击 `dropLabel`，同时断言 `hoverDrop !== null && hoverEnemy === null`。

## 2026-11-14（续）— 多件掉落竖排展开：按「牌面重叠」分堆，不按半径

- 需求（用户）：「各种物品重叠在一起时竖着垂直展开，限制展开数量，优先展示高品质」，
  参照暗黑打 boss 一次爆一地装备的名字列表。
- 关键判断：分堆依据用**牌面框是否重叠**（并查集传递合并），而不是「距掉落点 N px」。
  半径法会把两件肉眼分得开的物品硬塞进一列；牌面重叠则严格等价于「这些名字本来会互相盖住」。
- 展开方向：**品质高的在最上面**、列底锚在品质最高那件的默认牌位。这样
  ① 单件掉落的位置与改造前完全一致（`count=1` 时公式退化为原牌位）；
  ② 列表从上往下读就是品质顺序；③ 捡走顶部一件后整列合拢、第 6 件自动补位，不会留洞。
- 溢出策略：超过 `DROP_LABEL_MAX=5` 的掉落物 **`label = null`（无牌）但小模型仍可点**。
  绝不能为了排版把物品变成不可拾取；这条写进了 CONTEXT 不变量 19。
- 踩坑：想用真实战斗截一张「6 件一堆」的图，发现**当前掉落是一次击杀一件**，两只怪即使在
  同一入口出现、被同一位置击杀，死亡点仍差 40–90px，牌面根本不重叠 —— 也就是说这个功能
  目前只在「多件掉落」或「连续击杀落在同一小块地」时才触发。视觉验证最后用临时补丁
  （一次击杀克隆 6 件）+ 临时探针脚本截图完成，**补丁与脚本都已删除**，别把它们当成运行时行为。
- 另一条观察：牌面盖住怪物躯干是**设计如此**（点名字优先拾取）。所以「怪物死在一堆战利品上」
  时，点它胸口会先捡东西；想继续砍要点头部（躯干中心 -30 在牌带 [-54,-34] 之下）。
  这是用户明确要的优先级，不是回归。

## 2026-11-14（晚）— 走路/转身相位写在 combat，绘制层不许自己猜

- 需求（用户）：人物和怪物要「有移动和转身动作」，不能一直平移。
- 关键判断：**相位属于状态，不属于绘制**。`stride` 必须在 `walk()` / `updateSkeletons()` 里
  按**碰撞后真正走了多远**累加（`STRIDE_PIXELS=22`）；如果让 `paint.ts` 用 `s.t * k` 自己编帧，
  就会出现「顶着墙还在原地踏步」「走慢时脚底打滑」两种必然的错误，而且无从断言。
- 同理，`Skeleton.face` 每帧指向玩家（哪怕站着不动），`swing` 由**出手**写、命中与否都播；
  否则绘制层要么得猜怪物想干什么，要么只能画一个永远朝前的立牌。
- 踩坑：`moving` 这个布尔值看着冗余（速度 > 0 不就行了？），但被身体碰撞推着走 / 被墙卡住时
  `vx,vy` 非零而位移为零，只能靠它区分「真的在走」和「推不动」。没有它，怪会定格在
  「抬着一条腿」的姿势上。
- 验收要点：新增的 4 条 movement 断言全部只看状态（朝向的 `cos` 符号、`stride` 是否推进、
  `swing>0`、`moving===false`），不依赖任何像素；像素只由 playthrough 截图人工看。

## 2026-11-15 — 技能第一批：法力是「不会自己长回来」的资源

- 需求（设计文档 8.2 / 8.3 / 9.3，第一批）：7 格技能栏、法力、CD、读条与打断、蓝药。
- 关键判断一：**死亡 / 掉落只有一个入口**。原来「扣血 + 击退 + 死亡 + 击杀计数 + 加权掉落」
  整段埋在 `attack.ts::swingAtTarget()` 里。技能如果自己写 `sk.hp -= x`，技能击杀就不会掉战利品、
  `kills` 也不涨。所以先抽 `damageSkeleton(s, i, amount, opts)`，普攻与所有技能都调它；
  `skills.test.ts` 有专门一条「a skill kill drops loot exactly like a sword swing」守着。
- 关键判断二：**拒绝必须免费**。`beginSkill()` 的 `cooling / mana / empty / busy / ended`
  全部不扣蓝、不进冷却。否则连按两下就自己把蓝扣光，玩家会觉得「按了没反应还掉蓝」。
- 关键判断三：**打断的代价 = 蓝 + 冷却**。受击 / 闪避打断读条后不退蓝、冷却照走，这条写进
  CONTEXT 不变量 28。改软了，「站桩读条」就没有风险，PVP 里的打断也就没意义。
- 踩坑一：`advanceCast()` 的调用位置。放在 `updateSkeletons()` **之前**会晚一帧才断，
  受击的同一帧读条还在涨进度；现在排在 `updateExtraction()` 之后、`updateSkeletons()` 之后。
- 踩坑二：**读条也要钉住玩家**。只把 `channel` 当成「不能动」的条件时，读条中点击地面仍会走路，
  读条就变成「边跑边放」。现在 `step()` 用 `pinned = s.channel !== null || s.cast !== null`。
- 踩坑三：技能伤害要过 `mods.damageMultiplier()`（星图乘区），不然接星图时要回头改每个技能。
- 踩坑四：HUD 布局。底部中央原本是「武器槽 + 引导进度」；技能栏插进去后，把**引导进度条挪到
  顶部计时胶囊下方**、把「按 E 引导」提示挪到技能栏上方（`VIEW_H-186`），否则 1280×600 下
  技能栏与引导面板重叠。清场文案与引导面板同时出现时只画引导面板。
- 美术：技能图标必须是体素模型（`SKILL_ICONS`），`skills.test.ts` 断言每个 `SkillDef.icon`
  都能解析出模型 —— HUD 上不许再出现 ⚔ 这类字形。

## 2026-11-15（第二批）— 技能表现：先有「过程」，再谈「好看」

- 需求（用户）：「所有技能都是瞬发的，也没有足够多的特效和粒子效果，让人根本看不出来放的是
  什么技能」「冲锋直接变成了瞬移，怎么也要有一个冲过去的过程」。
- **瞬移的根因不是动画缺失，是实现方式错了**：旧 `dash()` 沿方向一次循环走完 220px，
  渲染层永远只看得到起点和终点。改成分帧（`DASH_SPEED=950`，每帧 `canStand` + 沿途结算）
  之后，「过程」自然就有了 —— 残影、拖影、落地尘土都是顺带的。
- **零长度帧会杀掉位移**：改成分帧后浏览器实测只冲出 117px 就停了。原因是用
  「本帧位移 < 0.5px」判撞墙，而输入事件那一帧 `dt = 0`，位移本来就是 0。现在
  `dt <= 0` 直接 return，`blocked` 必须满足 `step > 0.5`。**任何「按位移判断状态」的分帧逻辑
  都要先处理 dt = 0**。
- **截图拍不到 0.3 秒的闪光**：`play.screenshot` 从调用到成像有 1~2 秒的游戏时间延迟，
  0.3~0.8 秒的特效必然错过。解法不是把闪光拖长（那会像卡帧），而是补一层**地面残留**
  （灼痕 / 霜痕，3.2 秒）：玩家在技能放完后仍读得出「刚才往哪边打的」，录像和截图也拍得到。
- **线性淡出 = 看不见**：`alpha = life/max` 会让特效一半寿命都在半透明里。改成
  `life/(max*0.55)`，前 45% 全亮、后段才淡，读起来是「一闪 + 余晖」。
- **特效只写不读**：所有 `skillFx` 都由战斗层写（它知道打中了谁、朝哪个方向），绘制层
  只按 `kind` 画形状。反过来让绘制层猜，就会出现「画面上的扇形和实际命中范围不一致」。

## 2026-11-15（第三批）— 状态与反应链：先定「谁是唯一出口」

- 需求（设计文档 8.4 / 8.5）：「6 元素 5 反应」，8.4 的状态表从硬控到 DOT 22 条，8.8 要求「看不见
  就等于不存在」。
- **拆成两个文件不是洁癖，是为了打破环**：`attack.ts`（唯一伤害入口）需要在命中时上状态，
  而 DOT / 引爆 / 撞墙又都要回到 `damageSkeleton()` 结算。若状态表和伤害逻辑放一个文件，
  无论把 import 放哪边都成环（`status → attack → status`）。现在的切法：
  - `status.ts`：注册表 + 纯查询，**零 combat import**；
  - `reactions.ts`：附着 / 反应 / DOT / 区域，import `attack.ts`；
  - `attack.ts`：只 import `status.ts`（上眩晕）与 `world.ts`（撞墙判定）。
- **`applyStatus` 对未登记的 id 直接抛错**（`STATUS[id]` 为 undefined 就会崩）。这是故意的：
  状态是「玩家必须看得见」的东西，静默忽略等于上线一个看不见的 debuff。踩到的表现是单测里
  `Cannot read properties of undefined (reading 'duration')` —— 第一版测试把 `'burn'`（状态）
  当成元素传给了 `applyElement`，崩得很快，比它悄悄不生效好。
- **元素 —— 状态的双重身份**：一个状态可以既是 DOT 又是元素附着（点燃 = 火、中毒 = 毒、减速 = 冰）。
  这样「反应」不需要第二套附着容器：查身上有没有 `element` 与之成对的状态就行。
  代价是 `slow` 被冰「占用」，将来要加「泥地减速」得先想清楚它算不算冰。
- **技能必须覆盖 6 元素，否则反应表有一半是死的**：把技能从 3 个扩到 7 个（火墙 / 毒池 / 水浪 / 落雷），
  「风」没有格子了（7 格已满），于是**让冲锋承担风** —— 冲进火里把火吹旺，读起来也合理。
  这条写在 CONTEXT 与设计 15.0 里，星图 / 游侠批次再拆。
- **区域对玩家也生效**：地面效果不区分敌我。好处是「预铺地面要站远处放」真的成立，
  并且玩家侧状态终于有了来源；坏处是贴脸放火墙会烧到自己（playthrough 里火墙落点 70~160px、
  半径 92，玩家有可能吃到一跳）—— 这是可接受的代价，写进契约避免下次当 bug 修。
- **视觉必须能一眼分辨**：头部状态方块（硬控盖横杠 / 叠层点白点）、地面区域（不规则方块地皮）、
  四种新特效（火墙/毒池的方块环、水浪的三道水脊、落雷的折线闪电）。全部只用 `fillRect` /
  `drawPixelRing`，没有渐变与圆弧 —— 和体素红线一致。
- **冻结 1.5 秒拍不到**：`play.screenshot` 有 1~2 秒延迟，硬控类状态的截图必然错过。
  验收拆成两半：投影断言 `skeletons[].statuses` 里有 `freeze`（硬证据），截图只负责
  「冰面 + 状态条」这种长寿命的画面证据。

## 死亡掉落（2026-11-15 深夜）

- **遗物必须摆在能站人的格子上**：拾取半径是 50px 且要求寻路可达，直接按死亡点算坐标会
  落到墙里 / 尸体上 —— 每个落点都要过 `nearestWalkable()`。
- **`reset()` 不能无脑清 `drops`**：R 重开是「重玩这张图」，尸体遗物属于**图**而不是「本局」。
  已捡走的不在 `drops` 里，所以保留 `fromDeathDrop` 的项既不会复制、也不会一按 R 就把遗物扫没。
  清理全部掉落是 `deployRun()` 的事（新图 = 新世界）。
- **耐久放在 `Drop` 上，不要另开 `state.dropDurability` 映射**：掉落被捡走 / 被替换时，
  同一份数据自然消失，少一个会漏删的旁表。
- **投影的坐标空间要一致**：`dropPlates` 曾经拿世界坐标除 `VIEW_W`（相机在原点时"看起来是对的"），
  结果脚本点到的全是空地。凡是给脚本点的东西，一律 `scr()` 之后再归一化。

## 可破坏物 / 单局事件 / 惊醒模型（2026-11-16 凌晨）

- **没有沉睡就没有「惊醒」**：第一版想省掉 aggro 直接做「破坏会惊醒周围的怪」，但怪本来就一直在追人，
  这个机制会退化成一句空话。所以 `Skeleton.awake` 是这一批的**地基**，箱子只是它的第一个用途。
  代价是感知半径必须比夹具里两只怪的距离（482 / 617px）大，否则既有的「等它走过来」验收会全部超时 ——
  这条写成了 `data-driven.test.ts` 的断言，改表调小半径会立刻红。
- **箱子的点击盒要排在怪前面**：`hitTestEnemy()` 带 46px 容错（怪会跑，容错是为了手感），
  而箱子是静止的精确矩形。反过来的话，站在箱子边上的怪会把「指向箱子」那一下吃掉，
  玩家点了三下都在打怪 —— 和当年「掉落物 26px 吞掉整只怪」是同一类错误，只是方向相反。
- **`pinPlayer()` 抽到 `effects.ts`**：引导门 / 读条技能 / 砸箱子是三种「站桩」，
  第一版 `destructibles.ts` 抄了一份 6 行的清指令逻辑。抄第三份的时候就知道该抽了 ——
  两份会漂移（`pickupTarget` 漏清过一次），抽完 `extraction.ts` 少了一个私有函数。
- **被拒绝的起手要清 `smashTarget`**：守卫没清时每帧都满足「已到范围、还没起手」，
  不把意图清掉就会每 1/60 秒 toast 一次，两秒内刷屏 120 条。
- **事件必须排在 `updateRunClock()` 之后**：`elapsed = 900 - runSeconds` 读的是「这一帧刚更新的时钟」，
  排在前面会整体晚一帧。这类顺序错误在上一次「同一帧挨打同一帧断」里已经吃过一次教训，写进 CONTEXT 的不变量。
- **快进是可行的**：`play.advance(seconds)` 明确「pauses the App, steps whole frames, update only
  except the last rendered frame」—— 430 秒只要一百多步、十几秒真实时间。所以「第 7 分钟」的验收
  不需要真的等 7 分钟。前提是玩家别在这 430 秒里被打死：真地图 + 玩家不动 = 只有感知圈内的 1~2 只怪会来，
  其余沉睡（这正是沉睡模型的效果），清掉来的那几只就能安全快进。
- **`story` 清场会停表**：`runFinished()` 含 `cleared`，所以夹具里「杀光怪再快进」永远走不到 420 秒。
  事件验收因此改走真地图（7 只怪，远处的不来），而不是给游戏加一个「测试用时间跳转」的旁路。

## 「砸掉的木箱 6 秒后又回来了」（2026-11-16，用户实测）

- **症状**：砸开木箱、走开一会儿，木箱原地重新出现，还能再砸一次（战利品也能再刷一份）。
- **根因**：把「已破坏」这个**状态**塞进了 `rubble`（残骸倒计时）里。
  所有判定都写成 `rubble > 0`，而残骸 6 秒后归零 → 箱子同时被当成"完好的"：
  绘制画出来、`destructibleAtPoint()` 能命中、`beginSmash()` 也放行。
- **修法**：加 `DestructibleObj.broken` 作为**唯一且不可逆**的判据，
  `rubble` 降级成纯表现（还剩几秒残骸）。命中 / 起手 / 绘制 / 小地图 / 投影 / 脚本全部改读 `broken`。
- **教训（和 feedback 40 的保险格是同一类错误）**：**时间驱动的视觉衰减不能当状态用**。
  一个字段一旦同时被「表现」和「规则」读取，它的清零就会变成一次隐式状态迁移 ——
  而且只在表现走完之后才发生，单测跑 0.1 秒根本碰不到。
  这类 bug 的正确测试方式是**推进超过表现寿命**再断言（`updateDestructibles(s, RUBBLE_SECONDS)`
  之后仍然 `broken === true`），而不是只测砸开那一瞬间。

## 「踩自己铺的火墙会掉血」（2026-11-16，用户实测）

- **症状**：放完火墙 / 毒池走进去，自己开始掉血。当时的 `CONTEXT.md` 还专门把它写成设计
  （「区域对所有人生效，包括玩家自己」）—— 所以这不能靠改一行 if 解决，得先把概念补上。
- **根因不是火墙，是「来源」只被当展示字段**：`Zone.source: string` 存的是 `'fire_wall'`，
  没有任何阵营信息；`updateZones()` 于是只能「圈内所有人都续状态」。DOT 也一样：
  `StatusInstance` 根本不记谁施加的，`tickHost` 只能无差别扣血。
- **修法**：新增 `combat/source.ts`（零依赖）：`DamageSource{owner,id,label}` + **唯一判定**
  `hurts(source, victim)`。区域、状态、DOT、弹道、技能、怪物出刀全部带来源；
  两个伤害出口在**扣血之前**判阵营。同阵营直接返回 false —— 不是「扣了再免」，
  所以连无敌帧、耐久、击退、惊醒、击杀计数都不会被自伤触发。
- **为什么必须做成「阵营」而不是「是不是自己」**：用户明确说了还有队友。
  `hurts()` 比的是 `source.owner === victim`，以后加队友只要让同一阵营覆盖多个身体，
  判定一行不用改；写成 `source.id === 'player'` 就得再改一遍。
- **教训**：**「伤害来源」是建模概念，不是日志字段**。只要有一处判定靠字符串特判
  （`if (source === 'fire_wall') continue`），下一条自伤就会从另一个入口回来
  （火球落地留火、毒雾扩散、以后的怪物技能）。要立的是「谁能伤谁」的规则，不是九个特例。
- **测试写法**：光测「自己的火墙不掉血」不够，必须成对测 symmetry ——
  「玩家铺的火不烧玩家」+「怪铺的同一片火烧玩家」+「怪也不被自己的火烧」+「world 伤所有人」。
  只测一边的话，把 `hurts()` 反过来写（谁都不伤）也能过。

## 「移动只有八方向、人不灵活」——根因在寻路，不在朝向（2026-11-16 晚）

- **症状**：用户说「人物本来就是八方向移动，玩法上太不灵活」。
- **误判风险**：很容易以为是朝向渲染只有四/八向。**不是** —— 那是视觉；操作上的
  八方向来自 `findPath`：A\* 跑在格子图上、8 邻接，返回的每个点都是**格中心**，
  所以不管点哪，轨迹只能是 0°/45°/90°。
- **修法**：`straightenPath()`（string pulling）—— 从当前位置贪心找最远的、能直线
  走过去的路径点，跳掉只为绕拐角而存在的格中心。空旷地图上路径塌成一段直线，
  点的方向就是走的方向；绕柱子时只在真拐点转弯。
- **必须带碰撞半径**：拉直用 `clearWalk(..., BODY_RADIUS)`，不能只判中心线 ——
  否则会切到墙角上（"路径说能过，身体过不去"）。
- **顺手收敛的重复实现**：玩家 `canStand`（四向，r=10）和怪物 `canStand`（只左右，
  r=8）合并成 `world.ts::canStandAt`。两份实现意味着同一堵墙有两种答案。
- **验收怎么量**：投影加 `playerWorld`。屏幕上量不出来（相机跟人走），而且归一化
  坐标 x/y 分母不同（1280/720）—— 脚本里给两个轴加同样的 0.16，45° 会变成 29°。
  这个 bug 让上一版朝向验收**假阳性通过**了一次：A\* 恰好给了 45°，掩盖了脚本算错。

## 「16 向渲染让人物都扁了」（2026-11-16 晚，同一轮）

- **症状**：用户看 16 向对照图：「人物都扁了」。
- **根因**：收窄系数从 0° 就开始线性衰减，45° 斜向也被压到 4 格。但 45° 在 2.5D 里
  是**四分之三视角**，宽度该接近正面；只有真侧过去（67.5°–90°）才该窄。
- **修法**：曲线改成 `k = 1 - 0.45·t^1.6`（t = 离正面角度 / 90°）——
  前 45° 几乎不收（5→5→4），67.5° 起明显收，90° 到 3 格。
  同时 45° 单独一档：**两只眼 + 面甲凸到一侧**，不能退化成单眼的"半张脸"。
- **教训**：体素尺度下「宽度」只有 5/4/3 三个值，9 个角度不可能靠宽度全区分，
  必须用第二维度（眼睛位置、面甲凸起、盔脊偏移）。**每加一档都要重新数一遍唯一性**
  （`yawcheck` 脚本比肉眼看图快）。

## 从「平面压扁」到「真体积投影」（2026-11-17，用户要求「模型加厚度 + 运行时投影」）

- **动机**：16 档平面方案里，转身只能靠横向收窄，用户看到的是「人都扁了」。这不是参数调不好，
  是**模型只有 1 块厚**这个前提错了：纸片转 90° 只能塌成一条线。
- **做法**：`volumeOf(front, back, name)` 把正 / 背两张平面合成 `BODY_DEPTH=4` 层的体积；
  `bake(model, override, yaw)` 把体素绕 y 轴转进相机空间、斜投影、按深度排序逐块画。
  任意角度都是几何算出来的 —— 不需要再手绘中间档，也不需要"压扁"。
- **厚度取值**：3 层（12px）侧看仍像柱子；4 层（16px）对 20px 宽的人物是合适比例
  （真人侧影约 8 成）。`leanZ`（头 +1 / 腿 -1）让正侧身有「头前腿后」的轮廓。
- **必踩的坑**：`shade()` 只解析 `#rrggbb`，却输出 `rgb(...)`。体积合成是"压暗后再压暗"，
  第二级拿到 `rgb(...)` → `parseInt('gb(...)', 16)` = NaN → 画出来**一片纯黑**。
  修法是让 `shade()` 也只输出 `#rrggbb`，颜色永远可再入。这个 bug 只在"调色结果再被调色"时出现，
  旧代码里模型颜色都是字面量 hex，所以从没暴露过。
- **缓存策略**：按 7.5° 量化的桶懒烘（`spriteOf(m, flash, yaw)`），key 必须含桶号 ——
  投影会改变 sprite 的宽高和锚点，共用 key 会画出拉伸的人。
- **代价**：每个 pose 从 60 块变成 240 块，首次遇到新档位要烘焙 ~1.5ms。走路时每秒最多换
  十来个档位，实测 playthrough 98 步无掉帧；稳态只 drawImage。

## 「人物移动反向」（2026-11-17，玩家截图报的）

- **症状**：往右下走，人物却像朝左后方（看到背面）。
- **根因**：`yawOf()` 写成 `face − π/2`，正确是 **`π/2 − face`**。
  脸朝向在相机空间是 `(sin(yaw), cos(yaw))`：朝屏幕右（face=0）时脸必须朝 +X，
  要 `yaw = +π/2`；写成 `face − π/2` 得到 `−π/2`，整个人左右镜像。
- **为什么之前的验收没抓住**：`playthrough-facing` 断言的是 **`playerFace`（逻辑朝向）**，
  而 bug 在渲染。逻辑对、渲染镜像 —— 这类错误只有**看截图**能发现，断言抓不到。
- **补的护栏**：单测里逐个方向核对「脸朝哪」：
  `facing(0) === [1,0]`、`facing(π/2) === [0,1]`、`facing(-π/2) === [0,-1]`……
  (`sin(yaw), cos(yaw)` 取整后与预期象限比对)。这能同时抓左右反和上下反。
- **教训**：凡是「逻辑值 → 视觉输出」的映射（角度、镜像、坐标轴符号），
  断言逻辑值是不够的，必须断言**映射后的方向**。这次是 yaw 符号，下次可能是 uv 或
  相机 up 向量。

## 武器瞬移 + 腿短撅屁股（2026-11-17，用户截图报的两条）

### 武器转向不连贯、会瞬移
- **两个独立原因叠加**：
  1. 肩位写成 `flip ? -1 : 1` —— **二值判断混进了连续量**。转身经过正下方时
     `cos(face)` 变号，肩膀两帧之间从 +14px 跳到 −14px。
  2. `p.face = atan2(...)` 是**直接赋值**，没有转身过渡 —— 点一个新方向，整个人
     （包括手臂）一帧内转 90°。
- **修法**：肩位 = `cos(π/2 − face) · SHOULDER_X · yawNarrow(face)`（连续过零点）；
  `face` 用 `dt * TURN_RATE` 追赶目标角（18/s ≈ 0.15 秒转完 90°）。
- **护栏**：`voxel.ts::shoulderOffset()` 提到渲染几何层（能被单测 import），
  测试扫整圈 720 个采样点，断言相邻 0.5° 的位移 < 1px。二值实现会给出 ~28px。
- **教训**：**连续量里不许出现二值判断**。位置、角度、缩放都该是 face 的连续函数；
  `flip` 这类东西只该用来选贴图，不该参与位置计算。

### 走路「腿短、撅屁股」
- **腿短**：`leg()` 只画 2 格腿身（总高 3 格），14 格高的人腿占 21%。改成 3 格腿身
  （总高 4 格），骑士仍 14 格（胸 4→3），骷髅 11→12 格。腿占比升到 29%。
- **撅屁股**：`leanZ` 给腿 `-1`（后移 1 格），腰在腿前面 → 视觉上臀部突出。
  **腿必须和前胸在同一条垂线上。**
- **另一个反效果**：把上半身 `+1`（头前伸）想补回轮廓，结果斜看时深度差变成横向
  偏移（X = x·cos + z·sin），45°–67° 看起来像**歪脖子**。所以 `leanZ` 最终归零：
  站姿就是一根笔直的柱子，立体感全部交给厚度和投影。
- **教训**：深度方向的偏移在正对时看不见、在斜看时变成横向偏移 —— 调"侧面轮廓"
  时要同时看 45° 和 90°，只看正对会以为没问题。
